# 협업 실행

## 시작과 재개

확정된 계획, 현재 작업 트리, 관련 기록을 확인한다.
프로젝트 기록의 탐색·현재 기준 확인은 스킬 본문에서 안내한 공통 읽기 절차를 따른다.
완료·진행·대기 작업과 실제 변경 상태를 먼저 대조해 compact나 재개 뒤 같은 작업을 중복 위임하지 않는다.
기록과 실제 상태가 다르면 현재 파일·검증 근거를 확인하고 차이를 남긴다.
타인의 기존 변경을 덮어쓰거나 되돌리지 않는다.

## 위임

각 작업에 다음을 전달한다.

- 목표와 프로젝트에서의 역할.
- 읽을 자료·관련 결정·전역 제약·정확한 공유 계약.
- 수정 가능한 파일·영역과 함께 수정하면 안 되는 공유 영역.
- 선행 작업과 시작 조건, 관찰 가능한 완료 기준.
- 필요한 검사와 결과를 반환할 위치·형식.

전체 대화를 복사하지 않는다. 자료가 크면 관련 파일·절·심볼을 지정한다.
독립 작업만 동시에 시작하고, 의존 작업은 필요한 산출물이 준비된 뒤 시작한다.
하위 에이전트가 임의로 추가 작업자를 만들지 않게 하고, 필요하면 메인이 재분할한다.
특정 모델을 일괄 강제하지 않는다. 사용자·프로젝트·실행 환경의 모델 제한과 선택을 따른다.

### 새로 띄울지 이어 맡길지

차례로 이어지는 작업을 맡길 때는 다음 작업이 앞 작업에서 읽은 자료를 다시 쓰는지로 가른다.

- 다시 쓴다: 같은 지침·설계 문서·코드를 읽어야 하는 다음 작업은 앞 작업을 한 작업자에게 이어 맡긴다. 실행 환경이 이어 맡기는 수단을 줄 때다. 작업마다 새로 띄우면 같은 자료를 작업 수만큼 다시 읽는다.
- 다시 쓰지 않는다: 읽을 자료가 겹치지 않는 작업, 동시에 돌릴 독립 작업, 만든 과정을 몰라야 하는 검증은 새로 띄운다. 이어 맡길 수단이 없거나 앞 작업자의 맥락이 거의 찼을 때도 새로 띄우고, 앞 작업의 결과와 읽을 위치를 넘긴다.

예: 회원 등급 기능을 DB 변경, 서버 처리, 화면 순서로 맡기는데 세 작업이 같은 설계 문서와 같은 모듈을 읽는다 → 한 작업자에게 이어 맡긴다. 결제 모듈 수정과 통계 화면 추가처럼 읽을 코드가 겹치지 않는다 → 따로 띄운다.

### 작업마다 맡기는 검사

검사를 작업마다 맡길지 통합할 때 한 번 할지는 그 검사가 무엇을 보는지로 가른다.

- 그 작업이 바꾼 것만 보는 검사(바뀐 기능의 테스트 파일, 단위 테스트, 타입 검사)는 작업마다 맡긴다.
- 전체를 다시 보는 검사(전체 E2E, 바뀐 화면 캡처, 화면에서 직접 해 보기)는 작업마다 맡기지 않고 통합할 때 한 번 한다. 작업마다 하면 같은 검사를 작업 수만큼 되풀이하고, 통합할 때의 검증이 같은 것을 또 본다.
- 뒤 작업이 모두 그 위에 쌓이는 작업(DB 구조, 공통 계약)은 그 작업 끝에 전체 검사를 한 번 한다. 거기서 틀리면 뒤 작업을 모두 다시 해야 해서다.
- 실패를 고친 뒤에는 실패한 검사만 다시 돌린다. 전체는 통합할 때 돌린다.
- 프로젝트 지침이 검사를 돌리는 때를 정해 두었으면 그 지침을 따른다.

## 진행 관리

- 메인은 의존성, 담당 범위와 주요 결정을 추적하고 독립적인 통합 준비를 진행한다.
- 에이전트가 반환할 내용은 상태, 변경 위치, 실제 검증 결과, 우려·질문이다. 큰 diff와 로그는 파일로 전달한다.
- 대기 중에는 가능한 작업을 하되 맡겨둔 영역을 중복 수정하지 않는다. 결과 조회는 환경이 제공하는 알림·적절한 대기 도구를 사용하고 잦은 짧은 폴링을 피한다.
- 공유 계약의 변경 필요가 드러나면 영향받는 작업을 조정하고 계약을 갱신한 뒤 전달한다. 중요한 설계 변경은 사용자와 논의한다.
- 실패·충돌은 원인을 확인해 해당 범위를 수정하거나 순차로 전환한다. 같은 실패를 무한히 재시도하지 않는다.
- 지속적으로 보존할 진행 변화는 스킬 본문에 따라 maintain-work-notes 스킬로 기록한다. 확정된 계획에 들어 있던 결정은 진행 기록과 함께 결정 문서에도 반영한다. 코드와 결정 문서가 어긋나지 않게 하기 위해서다. 모든 중간 출력을 메인 대화에 복제하지 않는다.

## 통합과 완료

작업자의 완료 주장만으로 끝내지 않는다. 변경 범위·인터페이스 일치·계획 대비 누락을 확인한다.
작업별 검사와 별도로 실제 통합 경로의 핵심 검증을 수행한다. 위임할 때 작업마다 맡기지 않은 전체 검사도 여기서 한 번 한다.
검증 스킬이 제공되면 사용할 수 있지만 필수 의존성으로 만들지 않는다.
남은 문제가 있으면 완료와 구분해 보고하고, 코드 이해를 위해 주요 입력부터 결과까지의 실제 흐름을 짧게 설명한다.
commit, push, 배포, 외부 메시지 전송은 해당 작업에 주어진 권한 범위에서만 수행한다.
