# 지식 베이스 설정

사서(`librarian`)와 기준 검수(`check-criteria`) 스킬이 읽고 쓸 지식 베이스를 준비한다. 지식 베이스는 일만이 아니라 생활·취향·상황까지, 에이전트가 모르는 사용자 맥락을 쌓는 곳이다. 한 번 하면 끝나는 일이라 사용자가 설정 파일을 열 일이 없게 하는 것이 목표다.
스킬이 지식 베이스에 기대는 것은 세 가지뿐이다. 색인(`INDEX.md`), 메모 위치(`raw/journal/`), 기준 문서 위치(`wiki/criteria/common.md`). `INDEX.md`와 `raw/journal/`이 있는 git 저장소를 지식 베이스로 알아본다. 규칙과 틀은 스킬 안에 있고, 지식 베이스에는 기록(맥락·데이터)만 둔다. 나머지 구조는 사용자가 바꿔도 된다.

아래 경로는 이 스킬 폴더 기준이다. 초안은 `assets/knowledge-base/`, 스크립트는 `scripts/`에 있다.

## 먼저 확인

`$KNOWLEDGE_BASE_DIR`이 이미 있으면 연결된 상태다. 사용자에게 "이미 연결돼 있다. 점검만 할지, 다른 저장소로 바꿀지"를 묻고 그에 맞게 간다. 없으면 아래 두 모드 중 하나를 묻는다. 사용자가 이미 말했으면 다시 묻지 않는다.

## 모드 1: 새로 만들기

1. 세 가지를 묻는다. 저장소를 둘 폴더(절대 경로), 저장소 이름, 소유자 표시 이름. GitHub CLI(`gh`)가 있으면 비공개 저장소도 만들지 함께 묻는다.
2. 초안을 복사하고 자리표시자를 치환한다.
   ```bash
   python3 "<이 스킬 폴더>/scripts/bootstrap.py" <폴더> --name <이름> --owner <소유자>
   ```
   이미 있는 파일은 건너뛴다. 기존 지식 베이스를 덮어쓰지 않는다.
3. `git init -b main` 후 첫 커밋. GitHub 저장소를 만들기로 했으면 `gh repo create <이름> --private --source . --remote origin`. push는 사용자에게 묻는다.
4. 아래 "설정 저장"을 한다.

## 모드 2: 기존 저장소 연결

1. 경로를 받는다.
2. 계약을 점검한다.
   ```bash
   python3 "<이 스킬 폴더>/scripts/check_contract.py" <폴더>
   ```
   필수 세 가지 중 실패가 있으면, 초안의 해당 파일을 보여 주고 추가할지 묻는다. 기존 파일은 고치지 않는다. 사용자가 자기 규칙을 이미 갖고 있을 수 있어서다.
   권장 항목이 없거나 `[경고]`가 나오면 왜 필요한지 한 줄과 함께 초안의 같은 파일을 보여 주고 추가나 수정을 제안한다.
   - 지식 베이스 안내 `CLAUDE.md`: 이 저장소가 지식 베이스라는 것, 여기서 연 세션은 프로젝트에 속하지 않는 대화(생활, 계획, 지식 베이스 관리)를 하는 곳이라는 것, 기록은 `task-workflow:librarian`을 따른다는 것만 둔다. 초안은 `assets/knowledge-base/CLAUDE.md`.
   - 상황판 `wiki/board.md`: 프로젝트마다 어디까지 왔는지 묶음 하나씩. 초안은 `assets/knowledge-base/wiki/board.md`.
   - git 저장소: 기록을 지우지 않고 이력으로 남기기 위해서다.
3. 아래 "설정 저장"을 한다.

## 설정 저장

```bash
python3 "<이 스킬 폴더>/scripts/save_setting.py" --dir <절대 경로> [--repo <원격 주소>]
```

`~/.claude/settings.json`의 `env`에 `KNOWLEDGE_BASE_DIR`과 `KNOWLEDGE_BASE_REPO`를 넣는다. 기존 설정은 보존한다. 환경 변수로 두는 이유는 모든 세션, 서브에이전트, 셸 명령에서 `$KNOWLEDGE_BASE_DIR`로 바로 보이기 때문이다. 사용자 설정 파일을 바꾸는 일이라 실행 전에 한 문장으로 알린다.

## 끝날 때

저장한 설정은 **다음 세션부터** `$KNOWLEDGE_BASE_DIR`로 보인다. 지금 세션에서 이어서 사서나 기준 검수를 쓰려면 경로를 직접 넘긴다. 이걸 말하지 않으면 사용자가 바로 다음 요청에서 "연결 안 됐다"는 답을 받는다.

두 줄로만 보고한다. 앞뒤에 다른 문장을 붙이지 않는다.
- **완료**: 만들었거나 연결한 경로, 계약 점검 결과, 설정 저장 여부
- **확인할 것**: GitHub 저장소 생성, 사용자 설정 파일 변경처럼 세션 밖에 남는 변경. 없으면 "없음"

## 하지 말 것

- 기존 지식 베이스 파일을 덮어쓰거나 고치지 않는다. 추가나 수정을 제안만 한다.
- push를 묻지 않고 하지 않는다.
- 초안 치환 외에 내용을 지어 넣지 않는다. 기록은 사서가, 기준은 실제 작업의 피드백이 만든다.
- 비밀값이나 자격 정보를 지식 베이스나 설정에 적지 않는다.
