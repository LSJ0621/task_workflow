# 색인

무엇이 어디 있는지 적어 둔 지도. 폴더를 뒤질 수 없는 환경에서는 여기서 시작한다.

## 이 지식 베이스는

에이전트가 모르는 맥락을 담는 곳이다. 나에 대한 사실(일, 생활, 취향, 상황), 정한 것과 이유, 문제가 있었던 일이 들어간다.
기록은 이렇게 만들어진다.

1. 낮: 작업 세션이 메모 한 줄을 남긴다(`raw/journal/`). 메모는 "어느 세션의 어느 때쯤"을 가리키는 표지다.
2. 새벽: 메모가 가리키는 세션 기록에서 그 대화를 스크립트로 뽑아 원본 기록(사례·결정·맥락)을 만든다. 처음에는 `status: draft`(확인 전)다.
3. 확인을 통과한 기록만 `status: active`(확정)가 된다. 확정된 기록만 `wiki/` 요약에 올라간다.

아직 기록이 안 된 오늘 일은 `raw/journal/`의 메모에서 직접 읽는다. 찾아도 쓸 만한 답이 없으면 `notfound` 메모를 남긴다(`task-workflow:leave-memo`).

## 읽는 순서

1. 항상: 지침 문서(전역 지침, 응답 양식). 세션에 자동으로 들어간다. 매번 알아야 하는 규칙은 거기에만 있다.
2. 세션 시작에 한 번: 이 색인. 무엇이 어디 있는지만 본다.
3. 필요할 때: `wiki/` 요약. 맥락 요약, 프로젝트 카드, 상황판. 지금 판단에 쓰는 기록만 올라가 있다.
4. 요약으로 부족할 때: 요약 줄에 적힌 id를 따라 `raw/` 원본 그 기록만 연다. `## 요지`를 먼저 보고, 사용자가 한 말이 필요하면 `## 있었던 일`을 본다. 에이전트가 한 말까지 필요하면 그 절 첫 줄이 가리키는 `raw/sessions/` 파일의 그 범위를 연다.
5. 오늘 일이라 기록이 아직 없을 때: `raw/journal/<오늘 날짜>.md`의 메모.

`status: draft`인 기록은 확인 전이다. 근거로 쓰지 않는다. `superseded`와 `archived`인 기록은 지금 판단에 쓰지 않는다. 예전에 있었던 일을 물을 때만 본다.

## 찾는 것 → 위치

| 찾는 것 | 위치 |
| :- | :- |
| 나에 대한 맥락(일, 생활, 취향, 도구) | `wiki/context.md` 도메인별 절. 원본은 `raw/context/` |
| 모든 프로젝트에 걸린 결정 | `wiki/context.md` "모든 프로젝트에 걸린 결정" 절. 원본은 `raw/decisions/` |
| 프로젝트가 뭐고 어디 있나, 그 프로젝트의 유효한 결정 | `wiki/projects/<slug>.md` (프로젝트 카드) |
| 프로젝트마다 어디까지 왔나 | `wiki/board.md` (상황판) |
| 사례가 어느 규칙과 이어지나 | `evolve/rule-cases.md` (규칙별 사례표) |
| 규칙을 고칠 때 무엇을 원인으로 봤고 그 추정이 맞았나 | `evolve/hypotheses.md` (추정 기록). 끝난 것은 `evolve/hypotheses-archive.md` |
| 주마다 지적 수와 규칙의 글자 수가 어떻게 바뀌었나 | `evolve/metrics.md` (측정값) |
| 스킬·훅·단계 같은 구조를 왜 더하거나 지웠나 | `raw/decisions/`에서 머리말 `tags`에 `structure`가 있는 결정 |
| 한 주 동안 규칙이 어떻게 바뀌었나 | `raw/reviews/` (점검 보고서). 변경 하나하나는 규칙이 있는 저장소의 커밋에 있다 |
| 오늘 메모(아직 기록이 안 된 일) | `raw/journal/<오늘 날짜>.md` |
| 문제가 있었던 일과 그때 오간 말 | `raw/cases/`. 어느 규칙과 이어지는지는 `evolve/rule-cases.md` |
| 이 저장소가 답해야 하는 질문 | `tests/regression.md` |
| 코드 저장소가 없는 작업의 산출물 | `work/<작업>/` |

## 폴더

- `raw/` 원본. 추가만 한다. 사례·결정·맥락은 머리말에 아래 칸이 있다
  - `scope`: `me`는 모든 프로젝트, `project:<이름>`은 그 프로젝트
  - `status`: `draft`(확인 전), `active`(확정. 지금 판단에 쓴다), `superseded`(새 기록이 대신함), `archived`(보관. 있었던 일로만 남긴다)
  - `source`: `session`(세션 기록에서 스크립트로 뽑음), `memo`(메모에서 옮김. 세션 기록을 못 찾았거나 예전 기록), `agent`(에이전트가 스스로 정한 구조 결정)
  - 본문은 `## 있었던 일`, `## 요지`, `## 분석`(사례만) 순서다. `source: session`이면 `## 있었던 일`의 `<!-- extract:start -->`와 `<!-- extract:end -->` 사이가 뽑은 글 그대로다. 사용자 말과 그때 부른 스킬·읽은 파일만 있다. 손으로 고치지 않는다
- `raw/` 아래 폴더
  - `raw/journal/` 날짜별 메모. 새벽에 기록이 되면 파일 끝에 `정리됨:` 줄이 붙는다. 마지막 `정리됨:` 줄 뒤의 메모는 아직 기록이 안 된 것이다
  - `raw/cases/` 문제가 있었던 일. 사용자가 고친 일과 지식 베이스에서 못 찾은 일(`tags`에 `notfound`). 한 건이 한 파일
  - `raw/decisions/` 결정과 이유
  - `raw/context/` 나에 대한 오래 맞는 사실. 머리말 `domain`으로 가른다
  - `raw/sessions/` 세션 발췌. 세션마다 파일 하나. 뽑은 글 전체가 범위마다 한 번씩 있다. 에이전트가 한 말까지 봐야 할 때만 읽는다
  - `raw/reviews/` 주 1회 점검 보고서(`YYYY-MM-DD.html`). 에이전트가 한 주의 규칙 변경을 분석해 쓴 문서다. 머리말이 없다
  - `raw/archive/` 예전 구조의 기록. 새로 쓰지 않는다
- `wiki/` 필요할 때 찾는 요약. 줄마다 원본 id가 있다. 지금 판단에 쓰는 확정된 기록(`active`)만 올라간다
  - `wiki/context.md` 맥락 요약. 도메인별 맥락과 모든 프로젝트에 걸린 결정
  - `wiki/projects/` 프로젝트 카드. 프로젝트마다 한 장. 정체·위치·관련 기록과 유효한 결정
  - `wiki/board.md` 상황판. 프로젝트마다 묶음 하나. 그 프로젝트의 지침 후보도 여기 쌓인다
- `evolve/` 자가 발전이 쓰는 문서. 작업 세션은 읽지 않는다
  - `evolve/rule-cases.md` 규칙별 사례표. 사례마다 관련 규칙과 규칙과 관계
  - `evolve/hypotheses.md` 추정 기록. 규칙 절마다 무엇을 원인으로 보고 무엇을 바꿨는지와 그 추정의 상태. 끝난 것은 `evolve/hypotheses-archive.md`
  - `evolve/metrics.md` 측정값. 주 단위 표
  - `evolve/signals/` 모은 말. 새벽 작업이 대화 기록에서 고른 지적, 되물음, 만족, 선택을 날짜마다 한 파일로 쌓는다
- `work/` 코드 저장소가 없는 작업의 산출물. 작업마다 폴더 하나
- `tests/regression.md` 회귀 질문

## 도메인 목록

도메인은 기록이 속한 영역 이름이다. 머리말의 `domain` 값이 이 이름을 쓴다.

- 맥락용 넷
  - `work` 일과 목표
  - `life` 일정과 생활
  - `taste` 소통 방식, 선호, 성향
  - `tools` 기기, 구독, 실행 환경
- 사례·결정용
  - `common` 모든 작업에 걸치는 기록

작업 도메인(기획, 개발 등)은 아직 없다. 사례·결정용으로 필요해지면 여기에 먼저 추가한다.
