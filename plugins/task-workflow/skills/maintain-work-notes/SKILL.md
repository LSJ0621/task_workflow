# 기록·정리와 재개

프로젝트의 의미와 근거를 보존하면서 필요한 내용만 찾아 읽을 수 있게 한다.
설계 내용과 폴더 분류를 미리 고정하지 않는다. 이 스킬은 기록·정리만 단독 수행할 수 있다.

## 위치와 진입점

- 사용자가 정한 위치와 기존 문서 관례를 우선한다. 없으면 프로젝트 안의 `docs/work-notes/`를 기본 후보로 사용한다. 기록 위치를 짧게 알리고, 작업 대상 프로젝트가 불분명하면 확인한다.
- 프로젝트별 기록 루트의 `INDEX.md`는 문서별 상대경로 링크·목적·다루는 내용·읽어야 할 상황을 안내하는 목차로만 유지한다. 서비스·정책 요약, 현재 진행 상태, 다음 작업, 미해결 쟁점의 상세 내용, 새 세션용 작업 지침은 넣지 않는다.
- 과제에서 지정한 제출 파일·경로·필수 내용은 그대로 유지한다. 기록이 분리돼 있어도 제출 양식이 요구하는 내용은 해당 제출물에 반영한다.
- 플러그인 배포 폴더나 사용자 전역 설정에 프로젝트 기록을 저장하지 않는다.

## 문서와 요청의 역할

| 위치 | 관리할 내용 |
| --- | --- |
| `INDEX.md` | 각 문서의 위치와 역할을 안내하는 목차 |
| `STATUS.md` | 지속적인 진행 기록이 필요할 때 현재 단계·완료한 주요 작업·다음 작업·진행을 막는 항목과 관련 문서 링크를 짧게 관리 |
| 기획·설계·정책·검증 등 주제별 문서 | 해당 주제의 요구사항·확정 정책·결정 근거·미정 항목의 상세 내용과 증거 |
| 프롬프트 | 이번 세션에서 수행할 구체적인 요청과 추가 지시 |

`STATUS.md`는 진행 상황을 지속적으로 보존할 필요가 있을 때 생성·사용한다. 단발성 자료 정리마다 의무적으로 만들지 않는다.
긴 작업 일지나 기획서 복사본으로 만들지 않고, 중요한 작업·단계·다음 작업·진행 장애가 바뀌었을 때 갱신한다. 진행 중·완료 표시, STATUS만 해시로 변경 확인, 완료 정리는 [STATUS 운영 규칙](references/status.md)을 따른다.
미정 정책의 상세 설명은 해당 주제 문서에 두고 STATUS에는 진행에 필요한 짧은 요약과 링크만 둔다. 같은 상세 내용을 두 곳에 복사하지 않는다.
지속적으로 보존해야 할 진행 상황을 프롬프트에만 남기지 않는다. 반대로 세션의 작업 지시를 INDEX·STATUS에 상시 명령처럼 옮기거나 과거 요청을 현재 실행 허가로 취급하지 않는다.

## 기록

- 중요한 결정, 작업 단계 전환, 인계·재개 전, 명시적인 기록 요청 시 관련 변경분을 반영한다. 매 메시지마다 모든 문서를 다시 쓰지 않는다.
- 다른 세션의 작업에 영향을 주는 요구사항·결정·검증 기준이 바뀌면 상세는 주제 문서에 기록하고, STATUS를 사용하는 프로젝트에서는 짧은 변경 요약과 해당 문서 링크를 반영한다. 문서 내용 변경만 있고 구현 진척이 없어도 필요한 알림을 누락하지 않는다.
- 사용자 요구·채택된 결정, 에이전트 제안·임시 가정, 미해결 쟁점을 구분한다. 결정의 이유, 근거 위치, 바뀐 경우 이전 결정과 변경 이유를 보존한다.
- 구현됨, 검사됨, 계획됨을 구분한다. 실행하지 않은 검증이나 관찰하지 않은 결과를 성공으로 적지 않는다.
- 대화 전체를 복제하기보다 작업에 필요한 결론·이유를 남긴다. 사용자가 원문 보존을 요구했으면 따른다. 기존 원문을 덜어낼 때는 실제 보존 여부를 확인하고 근거를 연결한다.
- 중요한 맥락을 압축하면서 수치·인터페이스·제출 조건을 바꾸지 않는다. 의견 충돌은 임의로 합의된 것으로 처리하지 않는다.

## 현재 문서와 Git 이력

문서 자체도 Git으로 버전 관리할 수 있다. 최신 기준과 중요한 과거 결정·폐기한 대안·변경 이유와 영향은 해당 주제 문서에, 지속적인 진행 요약은 필요한 경우 STATUS에 유지한다.
과거 문서 전체·대체된 상세 초안·정확한 diff는 필요할 때 Git에서 조회하고 현재 문서에 모두 복제하지 않는다.
Git 조회, 과거 원문 축약, 분할·병합의 출처 연결, 커밋 시점 판단이 필요할 때만 [이력 읽기·보존·커밋 규칙](references/history.md)을 읽는다.
Git이 없거나 해당 원문이 커밋되지 않았으면 Git에 있다고 가정하지 않고 로컬에 보존한다.

## 정리·이동과 재개

파일 분리·하위 폴더 생성·문서 이동을 할 때는 [문서 구조와 참조 규칙](references/organization.md)을 읽는다.
기존 정보는 역할에 맞는 문서로 유실 없이 분리·이동하고, INDEX와 역참조를 함께 수정한 뒤 로컬 링크를 확인한다.

처음 문서를 탐색하거나 구조가 바뀌었으면 INDEX로 위치를 파악하고 필요한 문서만 선택한다. 위치를 이미 알면 매번 INDEX를 다시 읽지 않는다.
새 세션·재개 시 STATUS가 있으면 본문을 읽고, 해당 작업에 필요한 주제별 문서와 그 안의 필요한 참조를 읽는다. 각 세션은 STATUS의 실제 경로·읽은 내용·해시를 기억한다.
이 스킬로 상태를 공유하는 세션에서는 각 요청 처리 전 STATUS만 `git hash-object --no-filters -- <STATUS 경로>`로 확인하고 `-w`는 사용하지 않는다. 해시가 달라졌거나 읽은 맥락을 기억하지 못하면 STATUS를 읽고 필요한 주제 문서의 현재 내용을 확인한다. INDEX·주제 문서·코드의 해시를 주기적으로 수집·비교하지 않는다.
STATUS가 없으면 관련 기록으로 확인되는 범위만 파악한다. 읽기만 요청받은 상황에서 STATUS나 변경 확인용 메타데이터를 만들지 않는다. 상태 요약을 파악하려고 코드를 다시 탐색하지 않고, 구현·검증이나 불일치 확인에 필요한 코드만 읽는다.
요구사항·정책·결정 이유·미정 사항의 상세 내용은 해당 주제 문서를 기준으로 확인한다. INDEX나 STATUS의 안내·요약으로 상세 내용을 대체하지 않는다.
정확한 과거 원문·변경 전후 비교가 필요하거나 기록 충돌을 확인해야 할 때만 관련 Git 이력으로 넓힌다. 모든 문서 읽기에서 Git 전체 이력을 조사하지 않는다.
현재 상태, 마지막으로 확인한 근거, 미해결 문제, 다음 행동을 짧게 보고한다.
재개 요청을 구현·재설계 허가로 해석하지 않는다.
스킬을 사용한다는 것만으로 모든 세션이나 compact 이후에 매 요청 자동 실행이 보장되지는 않는다. AGENTS 연결을 적용하지 않은 세션에서는 사용자가 새 세션·compact 후 스킬을 다시 지정해야 할 수 있다.

## 프로젝트 AGENTS 연결

프로젝트 적용·재개 지침 설정을 요청받으면 [AGENTS 연결 절차](references/project-guidance.md)를 읽고 해당 프로젝트의 기존 지침과 실제 기록 위치에 맞춰 최소한으로 반영한다. 일반 기록·조회 요청이나 플러그인 설치·업데이트만으로 AGENTS.md와 전역 설정을 수정하지 않는다.

## 위임과 출력

- 서브에이전트로 정리할 때는 기준 시점까지의 결정·근거 위치·수정 범위를 전달받아 정리한다. 이후 메인 세션의 새 논의를 실시간으로 안다고 가정하지 않는다.
- 같은 문서 집합의 작성자는 한 번에 하나로 정한다. 메인 세션은 새 결정을 모아 다음 요청으로 전달하고, 인계·제출 전 최신 반영 범위를 확인한다.
- 공유 작업 공간의 커밋은 메인이 조정한다. 정리 작업자는 변경 범위와 보존·검증 결과를 반환하고, 별도 위임 없이 커밋하거나 push하지 않는다.
- 채팅에는 기록 위치, 중요한 변경, 남은 쟁점만 짧게 알린다. 상세 기록을 다시 채팅에 붙이지 않는다.
