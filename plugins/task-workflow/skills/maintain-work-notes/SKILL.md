# 기록·정리와 재개

기록은 이후 작업자가 추측하면 틀릴 프로젝트 맥락을 보존한다. 사용자 의도, 현실의 제약, 논의에서 형성된 판단, 선택 이유와 당시의 전제를 중심으로 남긴다.
무엇을 기록할지는 [기록 가치 판단](references/organization.md#문서-역할과-기록-내용)으로 정한다. 기록할 설계 내용과 폴더 분류는 프로젝트에 맞춰 그때 정한다. 기록·정리만 단독으로 수행할 수 있다.

## 공통 원칙

모든 참조 문서에 적용한다. 참조 문서는 이 원칙을 반복하지 않고 필요한 곳에서 이 절을 가리킨다.

1. **요청한 만큼만 한다.** 상황 파악이나 재개 요청이면 읽고 보고한다. 문서의 "다음 작업"이나 과거 요청은 지난 세션 시점의 계획이라 그사이 바뀌었을 수 있으므로, "이어서 해"처럼 진행하라는 말이 있을 때 실행한다.
2. **필요해졌을 때 만든다.** 아래 항목은 표의 조건이 생겼을 때 만든다. 판단 질문은 "만들자마자 채울 내용이 있는가"다. 빈 구조는 읽을 곳만 늘리고 실제 쓰임과 어긋나기 때문이다.

   | 항목 | 만드는 조건 |
   | --- | --- |
   | 하위 폴더 | 같은 주제의 문서가 여러 개 생겼고, 묶으면 찾기 쉬워질 때. 이름은 문서 내용에서 정한다 |
   | 하위 INDEX | 그 폴더의 문서 목록 때문에 루트 INDEX가 너무 길어질 때 |
   | STATUS | 작업이 이번 세션에 끝나지 않아 다음 작업·세션이 이어받아야 할 때(인계, 단계 전환) |
   | 결정 ID | 다른 문서나 커밋 메시지에서 그 결정을 가리켜야 할 때 |

3. **정보마다 대표 위치는 하나다.** 다른 문서에는 요약 한 줄과 대표 문서 링크만 둔다. 복사본은 한쪽만 고쳐져 서로 어긋나기 때문이다.
4. **확인한 것만 확인했다고 쓴다.** 상태는 구현됨·검사됨·계획됨으로, 출처는 사용자 요구·채택된 결정, 에이전트 제안·임시 가정, 미해결 쟁점으로 나눠 적는다. 이유는 실제 논의와 근거에 있는 것만, 커밋 SHA는 실제로 조회되는 것만 적는다. 의견이 갈린 쟁점은 합의될 때까지 미해결로 둔다. 다음 작업자는 문서를 사실로 믿고 움직이기 때문이다.
5. **지우기 전에 보존을 확인한다.** 원문을 줄이거나 지우거나 STATUS를 비우기 전에, 그 원문이 실제 커밋에 들어 있는지 확인한다. 방법은 [원문 정리와 출처 보존](references/history.md#원문-정리와-출처-보존)에 있다. 들어 있지 않으면 먼저 커밋한다. 커밋할 수 없으면 원문을 그 자리에 그대로 두고, 커밋이 필요하다고 알린다. 다른 문서로 내용을 옮긴 것은 원문 보존이 아니다. 커밋되지 않은 원문은 지우면 되돌릴 수 없기 때문이다.
6. **바꾸는 범위는 최소로 한다.** 지금 생긴 탐색 문제를 푸는 만큼만 고친다. 요청 범위를 넘는 재편이나 내용 삭제가 필요하면 먼저 제안한다. 구조를 크게 바꾸면 다른 세션의 링크와 기억이 깨지기 때문이다.
7. **커밋은 허가된 범위에서 메인만 한다.** 커밋 여부는 사용자·프로젝트 지침과 이미 받은 권한을 따르고, 공유 작업 공간에서는 메인이 커밋을 조정한다. push, 이력 재작성(amend, rebase, force push), 저장소 초기화는 이 스킬의 범위 밖이다. 되돌리기 어렵거나 다른 작업에 영향을 주기 때문이다.

## 범위와 위치

- 사용자가 정한 위치와 기존 관례를 우선하고, 없으면 프로젝트의 `docs/work-notes/`를 기록 후보로 사용한다. 작업 대상이 불분명하면 확인한다.
- 기록은 해당 프로젝트 안에 둔다. 플러그인 배포 폴더와 사용자 전역 설정은 다른 프로젝트와 함께 쓰는 곳이기 때문이다. 지정된 제출 경로·양식은 보존한다.

## 작업별 참조

아래에서 현재 작업에 필요한 참조만 읽는다. 컨텍스트를 아끼기 위해서다.

허가된 기록 작성·인계 준비에서는 [기록 가치 판단](references/organization.md#문서-역할과-기록-내용)으로 필요한 내용을 선별한 뒤 위치를 구분한다. 현재 단계·완료한 주요 작업·다음 작업은 STATUS에, 요구사항·결정·근거·상세 기준은 주제 문서에, 문서 위치·목적·읽을 상황은 INDEX에 둔다.
진행 정보를 이후 작업·세션에 보존해야 하면 STATUS가 아직 없어도 [STATUS 관리](references/status.md)를 읽고 생성·갱신 필요성을 판단한다.

| 현재 작업 | 읽을 참조 |
| --- | --- |
| 문서 탐색·현재 상황 파악·인계받기·재개 | [공통 읽기 규칙](references/reading.md) |
| 논의·결정 기록, 문서 역할 판단, 폴더 정리·분리·이동 | [문서 역할·작성·구조 규칙](references/organization.md) |
| 지속적인 진행 기록이 필요할 때 STATUS 생성·갱신·완료 정리 | [STATUS 관리](references/status.md) |
| 정확한 과거 원문 조회, 원문 축약·제거, Git 출처·커밋 판단 | [Git 이력·보존·커밋 규칙](references/history.md)의 필요한 절 |

여러 작업이 겹치면 필요한 참조만 추가한다.

## 위임과 출력

- 정리를 위임하면 기준 시점까지의 결정·근거·수정 범위를 전달하고, 같은 문서 집합의 작성자를 하나로 정한다. 위임 뒤에 나온 논의는 작업자에게 자동으로 전달되지 않으므로, 메인이 새 결정을 모아 다음 기록 요청으로 넘긴다.
- 메인은 인계·제출 전에 최신 결정이 어디까지 반영됐는지 확인한다.
- 정리 작업자는 변경 범위와 보존·검증 결과를 반환한다. 커밋은 원칙 7에 따라 메인이 한다.
- 채팅에는 기록 위치, 중요한 변경, 남은 쟁점만 짧게 알린다. 읽기·재개에서는 현재 상태와 확인 근거·다음 행동을 보고한다.
