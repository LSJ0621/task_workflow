# 기록·정리와 재개

프로젝트의 의미와 근거를 보존하면서 필요한 내용만 찾아 읽을 수 있게 한다.
설계 내용과 폴더 분류를 미리 고정하지 않는다. 기록·정리만 단독 수행할 수 있다.

## 범위와 위치

- 사용자가 정한 위치와 기존 관례를 우선하고, 없으면 프로젝트의 `docs/work-notes/`를 기록 후보로 사용한다. 작업 대상이 불분명하면 확인한다.
- 기록은 해당 프로젝트 안에 두고 플러그인 배포 폴더·사용자 전역 설정에 저장하지 않는다. 지정된 제출 경로·양식은 보존한다.
- 재개·읽기 요청을 구현·재설계나 파일 수정 허가로 해석하지 않는다. AGENTS 연결은 프로젝트 적용·재개 지침 설정을 요청받았을 때만 수행한다.

## 작업별 참조

아래에서 현재 작업에 필요한 참조만 읽는다. 읽기만 할 때 작성·정리·완료 처리 참조까지 일괄 로드하지 않는다.

허가된 기록 작성·인계 준비에서는 작성할 내용을 먼저 구분한다. 현재 단계·완료한 주요 작업·다음 작업은 STATUS에, 요구사항·결정·근거·상세 기준은 주제 문서에, 문서 위치·목적·읽을 상황은 INDEX에 둔다.
진행 정보를 이후 작업·세션에 보존해야 하면 STATUS가 아직 없어도 [STATUS 관리](references/status.md)를 읽고 생성·갱신 필요성을 판단한다.

| 현재 작업 | 읽을 참조 |
| --- | --- |
| 문서 탐색·현재 상황 파악·인계받기·재개 | [공통 읽기 규칙](references/reading.md) |
| 논의·결정 기록, 문서 역할 판단, 폴더 정리·분리·이동 | [문서 역할·작성·구조 규칙](references/organization.md) |
| 지속적인 진행 기록이 필요할 때 STATUS 생성·갱신·완료 정리 | [STATUS 관리](references/status.md) |
| 정확한 과거 원문 조회, 원문 축약·제거, Git 출처·커밋 판단 | [Git 이력·보존·커밋 규칙](references/history.md)의 필요한 절 |
| 프로젝트 AGENTS.md에 재개 지침 연결 | [AGENTS 연결 절차](references/project-guidance.md) |

여러 작업이 겹치면 필요한 참조만 추가한다. 원문을 축약·제거할 때는 실제 보존 여부를 먼저 확인한다.

## 위임과 출력

- 정리를 위임하면 기준 시점까지의 결정·근거·수정 범위를 전달하고 같은 문서 집합의 작성자를 하나로 정한다. 이후 논의가 실시간 공유된다고 가정하지 않는다.
- 메인은 새 결정을 모아 다음 기록 요청으로 전달하고 인계·제출 전 최신 반영 범위를 확인한다.
- 공유 작업 공간의 커밋은 메인이 조정한다. 정리 작업자는 별도 위임 없이 커밋·push하지 않고 변경 범위와 보존·검증 결과를 반환한다.
- 채팅에는 기록 위치, 중요한 변경, 남은 쟁점만 짧게 알린다. 읽기·재개에서는 현재 상태와 확인 근거·다음 행동을 보고한다.
