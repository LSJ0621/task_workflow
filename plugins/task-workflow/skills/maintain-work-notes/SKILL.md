# 기록·정리와 재개

프로젝트의 의미와 근거를 보존하면서 필요한 내용만 찾아 읽을 수 있게 한다.
설계 내용과 폴더 분류를 미리 고정하지 않는다. 이 스킬은 기록·정리만 단독 수행할 수 있다.

## 위치와 진입점

- 사용자가 정한 위치와 기존 문서 관례를 우선한다. 없으면 프로젝트 안의 `docs/work-notes/`를 기본 후보로 사용한다. 기록 위치를 짧게 알리고, 작업 대상 프로젝트가 불분명하면 확인한다.
- 프로젝트별 기록 루트에 `INDEX.md`를 진입점으로 유지한다. 현재 상태·미해결 쟁점·다음 작업을 짧게 적고, 문서별 상대경로 링크·내용·읽어야 할 상황을 안내한다.
- INDEX는 전체 내용의 복사본이 아니다. 현재 유효한 결정·설계·검증 근거가 있는 위치를 가리킨다.
- 과제에서 지정한 제출 파일·경로·필수 내용은 그대로 유지한다. 기록이 분리돼 있어도 제출 양식이 요구하는 내용은 해당 제출물에 반영한다.
- 플러그인 배포 폴더나 사용자 전역 설정에 프로젝트 기록을 저장하지 않는다.

## 기록

- 중요한 결정, 작업 단계 전환, 인계·재개 전, 명시적인 기록 요청 시 관련 변경분을 반영한다. 매 메시지마다 모든 문서를 다시 쓰지 않는다.
- 사용자 요구·채택된 결정, 에이전트 제안·임시 가정, 미해결 쟁점을 구분한다. 결정의 이유, 근거 위치, 바뀐 경우 이전 결정과 변경 이유를 보존한다.
- 구현됨, 검사됨, 계획됨을 구분한다. 실행하지 않은 검증이나 관찰하지 않은 결과를 성공으로 적지 않는다.
- 대화 전체를 복제하기보다 작업에 필요한 결론·이유를 남긴다. 사용자가 원문 보존을 요구했거나 기존 원문 기록이 있으면 보존하고 요약에서 참조한다.
- 중요한 맥락을 압축하면서 수치·인터페이스·제출 조건을 바꾸지 않는다. 의견 충돌은 임의로 합의된 것으로 처리하지 않는다.

## 정리·이동과 재개

파일 분리·하위 폴더 생성·문서 이동을 할 때는 [문서 구조와 참조 규칙](references/organization.md)을 읽는다.
구조 변경 후 INDEX와 역참조를 함께 수정하고 로컬 링크를 확인한다.

재개 시에는 INDEX, 현재 작업의 문서, 그 안의 필요한 참조 순으로 읽는다.
정보가 없거나 실제 코드·파일 상태와 다를 때만 검색을 넓힌다.
현재 상태, 마지막으로 확인한 근거, 미해결 문제, 다음 행동을 짧게 보고한다.
재개 요청을 구현·재설계 허가로 해석하지 않는다.

## 위임과 출력

- 서브에이전트로 정리할 때는 기준 시점까지의 결정·근거 위치·수정 범위를 전달받아 정리한다. 이후 메인 세션의 새 논의를 실시간으로 안다고 가정하지 않는다.
- 같은 문서 집합의 작성자는 한 번에 하나로 정한다. 메인 세션은 새 결정을 모아 다음 요청으로 전달하고, 인계·제출 전 최신 반영 범위를 확인한다.
- 채팅에는 기록 위치, 중요한 변경, 남은 쟁점만 짧게 알린다. 상세 기록을 다시 채팅에 붙이지 않는다.
