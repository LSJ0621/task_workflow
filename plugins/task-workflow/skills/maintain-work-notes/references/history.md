# 문서와 Git 이력의 읽기·보존·커밋

## 문서와 Git의 보존 경계

- 현재 주제 문서에는 요구사항과 설계에 관한 결정·배경·제약·미정 사항과 가정을 보존한다. 기록할 내용의 선별 기준은 [문서 역할과 기록 내용](organization.md#문서-역할과-기록-내용)을 따른다.
- 중요한 과거 결정·선택 이유·폐기한 대안과 이유·결정 변경의 이유와 영향·실제 검증 결과와 한계는 현재 판단에 필요한 요약과 근거를 문서에 남긴다. 과거라는 이유만으로 Git에만 숨기지 않는다.
- 과거 문서 전체·대체된 상세 초안·단순 표현 수정·정확한 줄 단위 변경은 필요할 때 Git에서 조회한다. 사용자의 원문 보존 요구와 제출 양식이 우선한다.

## 과거 원문 조회

현재 상태를 읽는 절차는 [공통 읽기 규칙](reading.md)에 둔다. 여기서는 정확한 과거 내용이나 기록 충돌의 출처를 확인할 때만 조회 범위를 넓힌다.

1. 기록된 실제 커밋과 당시 경로부터 `git show <commit>:<path>`로 조회한다. 경로는 현재 위치가 아닌 해당 커밋 당시의 저장소 상대경로다.
2. 출처가 없으면 관련 파일의 `git log --follow -- <path>`나 결정 ID·고유 검색어를 사용한 `git log -S` 등으로 필요한 범위만 찾는다. `--follow`는 단일 파일의 이름 변경 추적이며 분할·병합을 완벽하게 복원한다고 가정하지 않는다.
3. 커밋·경로·절 또는 ID가 실제로 조회되는지 확인하고 원문과 이후 결정 요약을 구분해 답한다. 미래 커밋이나 추정 SHA를 적지 않는다.
4. 이력이 없거나 현재 clone에서 조회되지 않으면 미확인으로 남기고 현재 원문을 보존한다. 원격 접근·fetch가 필요하면 해당 작업의 권한을 따른다.

## 원문 정리와 출처 보존

- 중요한 결정에는 필요에 따라 안정적인 ID를 부여한다. 기존 ID는 이동·분할 후에도 유지하며 모든 메모에 기계적으로 ID를 붙이지 않는다.
- 원문을 축약·제거하기 전에 `git status`·diff와 과거 파일 내용을 대조해 보존할 원문이 해당 커밋에 실제로 들어 있는지 확인한다. HEAD가 있다는 것만으로 미커밋 원문도 보존됐다고 판단하지 않는다.
- 아직 커밋되지 않은 보존 대상이 있으면, 허가된 범위에서 스냅샷 커밋을 만들거나 원문을 로컬 문서로 유지한다. 커밋 권한이 없다는 이유로 원문을 삭제하지 않는다.
- 완료한 STATUS 내용을 비울 때도 실제 커밋에 덜어낼 원문이 있는지 확인한다. 필요한 결정·근거는 주제 문서에 남기고 STATUS 파일은 유지한다. 미완료 작업이 남았으면 완료 정리를 하지 않는다. 변경 확인용 파일 해시는 원문 보존의 증거가 아니며 커밋 SHA와 구분한다.
- 단순 파일 이동은 기존 링크 갱신으로 충분할 수 있다. 분할·병합·대폭 수정처럼 추적이 모호해지는 경우에는 관련 현재 문서에 **이동 전 커밋 SHA + 당시 경로 + 절 또는 결정 ID**를 남긴다. 가능하면 전체 SHA를 사용한다.
- 참조는 실제로 존재하는 이전 커밋을 가리킨다. 현재 작성 중인 커밋 자신의 SHA를 문서에 미리 넣으려 하지 않는다.
- INDEX에는 문서 위치·역할을, 관련 주제 본문에는 필요한 과거 출처를 둔다. 같은 이력 전체를 여러 문서·STATUS·INDEX에 복사하지 않는다.
- Git이 없는 프로젝트에서는 필요한 원문·변경 배경을 문서에 보존한다. 기록 정리를 위해 임의로 저장소를 초기화하지 않는다.

## 커밋 시점과 소유권

| 상황 | 기본 판단 |
| --- | --- |
| 읽기·과거 조회만 수행 | 커밋하지 않음 |
| 중요한 결정·설계·검증 기록 완료 | 의미 있는 논의 또는 작업 단위가 정리됐을 때 확정 |
| 원문을 축약하거나 구조를 재편하기 전 | 보존해야 할 미커밋 내용이 있다면 먼저 보존 |
| 파일 이동·분할·병합 완료 | INDEX·역참조·과거 출처를 확인한 뒤 구조 변경 단위로 확정 |
| 내용·결정 변경 | 가능하면 구조 변경과 분리해 이유가 드러나는 단위로 확정 |

커밋 수행 여부는 사용자·프로젝트 지침과 이미 부여된 권한을 따른다. 매 저장마다 커밋하거나 기존 허가를 매번 다시 묻는 절차로 만들지 않는다.
공유 작업 공간에서는 메인이 커밋을 조정하고, 정리 작업자는 별도 위임 없이 커밋하지 않는다.
커밋 전 기존 staging과 작업 트리를 확인한다. 관련 경로만 stage하고, 이미 staged된 다른 작업의 변경까지 함께 커밋하지 않는다. 다른 변경을 임의로 reset·stash하지 말고 작업 소유자와 조정한다.
커밋 메시지에는 변경 목적과 구조 이동의 대응 관계를 필요한 만큼 남긴다. 중요한 결정 이유는 메시지에만 숨기지 않고 현재 문서에도 유지한다.
커밋·원문 확인을 위해 amend·rebase·force push 같은 이력 재작성을 요구하지 않는다. push·공개·배포는 별도의 권한 범위다.

참고: [git log](https://git-scm.com/docs/git-log), [git show](https://git-scm.com/docs/git-show).
