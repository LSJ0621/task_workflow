# 공통 읽기 규칙

문서 탐색·상태 파악·분석·검증에 필요한 현재 기준을 확인할 때 사용한다. 다른 스킬도 이 문서로 바로 들어오므로, 읽기의 범위를 여기에 직접 적는다.
읽기 요청에서 하는 일은 읽기와 보고까지다. 문서·STATUS·AGENTS 수정이나 구현은 그 작업을 요청받았을 때 한다. 문서에 적힌 "다음 작업"은 지난 세션 시점의 계획이라, "이어서 해"처럼 진행하라는 말이 있을 때 실행한다([공통 원칙](../SKILL.md#공통-원칙) 1).

## 위치와 기준 문서

1. 사용자가 지정한 자료와 기록 위치를 우선한다. 처음 탐색하거나 구조가 바뀌었으면 해당 기록 폴더의 INDEX가 있을 때 먼저 읽고 필요한 문서만 선택한다. 위치를 이미 알면 INDEX를 건너뛴다.
2. STATUS가 있으면 진행 상황을 확인하고 해당 작업에 필요한 주제별 문서·절을 읽는다. 요구사항·정책·결정 이유·미정 사항의 상세는 해당 문서의 현재 내용을 기준으로 한다. INDEX와 STATUS에는 위치와 요약만 있기 때문이다.
3. 기록이 없으면 주어진 자료와 현재 대화에서 확인되는 범위로 수행하고, 진행 상황은 확인된 만큼만 말한다. 기록 체계는 기록 요청이 있을 때 만든다. 분석·검증의 근거는 관련 기준 문서의 실제 내용으로 확인한다.
4. 정확한 과거 원문·diff가 필요하거나 현재 기록의 모순·출처를 해소해야 할 때 [Git 이력](history.md)의 과거 조회 절로 넓힌다. 모순은 현재 문서와 필요한 실제 파일부터 대조한다. 상태 요약만 필요하면 문서로 충분하다.

## STATUS만 해시로 변경 확인

STATUS를 읽으면 그 순간의 해시를 `(작업 공간 내 실제 경로, 해시)`로 본문과 함께 기억한다. STATUS를 쓰는 세션에서는 요청을 처리하기 전마다 해시만 다시 계산한다. 같으면 기억한 내용을 쓰고, 다르면 STATUS와 현재 작업에 필요한 주제 문서·절을 다시 읽는다. 다른 세션이나 사용자가 STATUS를 고쳤는지 알아내기 위한 장치다. STATUS가 없으면 이 확인을 건너뛴다.

- 해시는 `git hash-object --no-filters -- <STATUS 경로>`로 구한다. `-w`를 붙이면 저장소에 객체가 기록되고, HEAD·최근 커밋·`git status`는 커밋하지 않은 수정을 반영하지 못하기 때문이다. Git 명령을 쓸 수 없으면 STATUS를 직접 읽는다. 이 확인을 위해 Git 설치·초기화·커밋을 요청할 필요는 없다.
- 본문을 기억하지 못하면(새 세션, 재개, compact 뒤) 해시가 같아도 본문을 다시 읽는다. 해시는 바뀌었는지만 알려줄 뿐 내용을 담고 있지 않기 때문이다.
- 읽기 전후의 해시가 같을 때 그 해시를 본문과 짝지어 기억한다. 읽는 동안 바뀌면 한 번 더 읽고, 그래도 계속 바뀌면 작성자와 조정한다.
- STATUS가 삭제·이동됐거나 조회가 실패하거나 내용이 맞지 않으면, 기억한 상태를 버리고 필요하면 INDEX에서 새 위치를 찾는다.
- 이 확인의 대상은 STATUS 한 파일이다. 다른 문서의 변경, 동시 편집 잠금, 원문 보존 여부는 알려주지 않는다. 다른 세션이 확인한 것도 이 세션이 읽은 것으로 치지 않는다.

## 재개 범위와 한계

재개는 상황 파악이다. 다음 작업의 실행은 이 문서 첫머리의 규칙을 따른다.
compact 뒤에는 읽기 규칙 자체를 잊을 수 있다. 프로젝트 AGENTS의 기록 스킬 사용 안내 또는 사용자 재호출을 진입점으로 사용한다. 자동 복구는 실제로 확인했을 때만 보장된다고 보고한다.
현재 기록으로 답할 수 있으면 거기서 멈춘다. 작성·완료 정리·AGENTS 설정·커밋 지침은 그 작업을 할 때 읽는다.

해시 명령의 동작 근거: [git hash-object](https://git-scm.com/docs/git-hash-object).
