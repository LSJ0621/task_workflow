# 공통 읽기 규칙

문서 탐색·상태 파악·분석·검증에 필요한 현재 기준을 확인할 때 사용한다.
읽기 요청만으로 문서·STATUS·AGENTS를 생성·수정하거나 구현을 시작하지 않는다.

## 위치와 기준 문서

1. 사용자가 지정한 자료와 기록 위치를 우선한다. 처음 탐색하거나 구조가 바뀌었으면 해당 기록 폴더의 INDEX가 있을 때 먼저 읽고 필요한 문서만 선택한다. 위치를 이미 알면 INDEX를 매번 다시 읽지 않는다.
2. STATUS가 있으면 진행 상황을 확인하고 해당 작업에 필요한 주제별 문서·절을 읽는다. 요구사항·정책·결정 이유·미정 사항의 상세는 해당 문서의 현재 내용을 기준으로 한다. INDEX의 안내나 STATUS 요약으로 상세를 대체하지 않는다.
3. 기록이 없으면 주어진 자료·현재 대화에서 확인되는 범위로 독립 수행한다. 진행 상황을 추정하거나 읽기만 요청받은 상황에서 기록 체계를 새로 만들지 않는다. 분석·검증의 근거는 관련 기준 문서의 실제 내용으로 확인한다.
4. 정확한 과거 원문·diff가 필요하거나 현재 기록의 모순·출처를 해소해야 할 때만 [Git 이력](history.md)의 과거 조회 절로 넓힌다. 모순은 현재 문서·필요한 실제 파일과 먼저 대조하며, 모든 읽기에서 Git 전체 이력을 조사하지 않는다. 상태 요약만 파악하려고 코드를 재탐색하지 않는다.

## STATUS만 해시로 변경 확인

- 새 세션·재개 또는 기억이 사라진 경우 STATUS 본문을 읽고 `(작업 공간 내 실제 경로, 해시)`와 내용을 세션별로 기억한다. 해시만 남았다고 본문도 안다고 가정하지 않는다.
- 상태 공유 중인 세션에서는 각 요청 처리 전 `git hash-object --no-filters -- <STATUS 경로>`로 비교값만 확인한다. 같은 경로·같은 해시이고 내용을 기억하면 재사용한다. 달라졌으면 STATUS를 읽고 현재 작업에 필요한 주제 문서·절을 확인한다. INDEX·주제 문서·코드로 해시 비교를 확대하지 않는다.
- STATUS를 읽기 전후의 해시가 같은지 확인해 본문과 대응하는 값을 기억한다. 읽는 동안 바뀌면 다시 확인하고, 계속 바뀌면 작성자와 조정한다. 무한 재시도하지 않는다.
- 삭제·이동·조회 실패나 알려진 내용 불일치가 있으면 이전 상태를 최신으로 취급하지 않는다. 필요하면 INDEX에서 새 위치를 찾는다. STATUS가 없으면 이 비교를 생략한다.
- `-w` 없이 계산해 Git 객체·staging·커밋·이력을 변경하지 않는다. 커밋하지 않은 현재 내용도 비교하며, HEAD·최근 커밋·`git status` 표시를 해시 대신 쓰지 않는다. Git 명령을 사용할 수 없으면 STATUS를 직접 읽고, 확인을 위해 설치·초기화·커밋을 요구하지 않는다.
- STATUS가 같아도 다른 파일이 같다는 뜻은 아니다. STATUS에 반영되지 않은 문서 변경을 자동 감지하지 않는다. 해시는 동시 편집 잠금이나 과거 원문 보존의 증거가 아니고, 다른 세션의 확인을 자신의 읽기 완료로 취급하지 않는다.

## 재개 범위와 한계

재개는 상황 파악이며 과거 요청·문서에 적힌 다음 작업을 현재 실행 허가로 취급하지 않는다.
compact 뒤 읽기 규칙 자체를 잊을 수 있다. 프로젝트 AGENTS의 기록 스킬 사용 안내 또는 사용자 재호출을 진입점으로 사용하며, 실제 자동 복구를 검증하지 않았다면 보장됐다고 보고하지 않는다.
현재 기록으로 답할 수 있으면 작성·완료 정리·AGENTS 설정·커밋 지침까지 추가로 읽지 않는다.

해시 명령의 동작 근거: [git hash-object](https://git-scm.com/docs/git-hash-object).
