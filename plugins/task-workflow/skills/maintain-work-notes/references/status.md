# STATUS 변경 확인과 운영

## 위치와 형식

기존 기록 관례와 사용자가 지정한 경로를 우선한다. 새로 필요하면 프로젝트의 기록 루트에 `STATUS.md` 하나를 두고 INDEX에서 연결한다. 기록 관례가 없으면 `docs/work-notes/`를 기본 후보로 사용한다. 작업·세션마다 별도 STATUS를 만들지 않는다. 기존 파일은 임의로 이동하지 않는다.

해시 비교 대상은 STATUS 하나다. 수동 변경 번호나 계산한 해시를 문서에 적지 않는다. 기존 수동 번호는 비교 기준으로 쓰지 않고, 허가된 기록 수정 시 내용 보존을 확인하며 제거한다. 읽기 요청만으로 파일 형식을 바꾸지 않는다.

```markdown
# 현재 작업 상태

상태: 진행 중
현재 단계: 예약 입력 검증 구현
완료한 주요 작업: 요청 형식 합의
다음 작업: 오류 응답 검증
진행을 막는 항목: 없음
관련 문서: [예약 정책](booking-policy.md)
```

본문은 진행에 필요한 요약과 링크만 유지한다. 상세 요구·결정·미정 정책·검증 근거는 주제별 문서에 둔다.

## STATUS 확인과 관련 문서 읽기

- 처음 탐색은 INDEX로 위치를 파악한 뒤 STATUS와 필요한 주제 문서를 읽는다. 각 세션은 STATUS의 `(작업 공간 내 실제 파일 경로, 해시)`와 읽은 내용을 기억한다. 새 세션·재개·compact 후 내용을 기억하지 못하면 STATUS 본문부터 읽는다. 해시만 남았다고 내용을 안다고 가정하지 않는다.
- 이후 상태 공유 중인 세션에서는 각 요청 처리 전 `git hash-object --no-filters -- <STATUS 경로>`로 비교값만 확인한다. 같은 경로·같은 해시이고 내용이 기억나면 재사용한다. 달라졌으면 STATUS를 읽고 현재 작업에 필요한 링크의 문서·절을 확인한다. INDEX·주제 문서·코드는 해시 비교 대상으로 확대하지 않는다.
- STATUS 읽기 전후의 해시가 같은지 확인해 본문과 대응하는 해시를 기억한다. 읽는 동안 바뀌었으면 다시 확인하고, 계속 바뀌면 작성자와 조정한다. 직접 수정한 STATUS도 저장 후 내용에 대응하는 해시로 갱신한다. 반복 재시도로 계속 읽지 않는다.
- STATUS 삭제·이동·조회 실패나 알려진 내용 불일치는 이전 상태를 최신으로 취급하지 않는다. 필요한 경우 INDEX로 새 위치를 찾는다. STATUS가 없는 프로젝트에서는 읽기 요청만으로 생성하지 않는다.
- `-w` 없이 계산해 Git 객체·staging·커밋·이력을 변경하지 않는다. 커밋 여부와 관계없이 현재 STATUS 내용을 비교하며, HEAD·최근 커밋·`git status` 표시를 본문 해시 대신 쓰지 않는다. Git 명령을 사용할 수 없으면 STATUS를 직접 읽는다. 이 확인을 위해 Git 설치·초기화·커밋을 요구하지 않는다.
- STATUS가 같아도 다른 파일이 같다는 뜻은 아니다. 중요한 문서 변경은 아래 갱신 규칙으로 STATUS에 요약·링크를 반영한다. 주제 문서에는 최신 내용·중요한 결정·변경 이유를 유지하고, 정확한 과거 원문·diff가 필요할 때만 [Git 이력 규칙](history.md)으로 조회한다. 분석·검증의 판단 근거는 필요한 기준 문서의 현재 내용으로 확인한다.
- 다른 세션의 읽기 완료를 자신의 확인으로 취급하지 않는다. 해시는 변경 감지용이며 동시 편집 잠금이나 과거 원문 보존의 증거가 아니다. compact 후 이 규칙 자체가 기억에서 빠질 수 있으므로 [AGENTS 연결](project-guidance.md)을 적용하거나 사용자가 스킬을 다시 지정하는 절차가 필요하다.

## 갱신과 완료

1. 중요한 진행 변화나 다른 세션에 영향을 주는 요구사항·정책·결정·검증 기준 변경이 생기면 관련 내용만 갱신한다. 상세는 주제 문서에, STATUS에는 짧은 변경 요약과 해당 문서·절의 링크를 둔다. 저장 직전 STATUS 해시를 확인하고 바뀌었거나 내용을 기억하지 못하면 최신 본문을 읽어 다른 세션의 변경을 보존한다. 충돌 시 작성자를 조정하며 읽음 표시·해시 저장 파일은 추가하지 않는다.
2. 현재 추적 중인 작업 전체에 미완료 작업·필요한 검증·미해결 장애가 없을 때 `상태: 완료`로 표시한다. 이번 요청이나 한 단계가 끝났어도 후속 작업이 남으면 진행 중으로 유지한다. 대기·중단·실패를 완료로 처리하지 않는다.
3. 완료한 내용을 비우기 전에 이후에도 필요한 결정·근거·검증 결과를 주제 문서에 보존하고 링크를 확인한다. 덜어낼 과거 상태 원문이 실제 Git 커밋의 해당 경로에 포함되는지도 확인한다. 보존·커밋 권한 판단은 [Git 이력 규칙](history.md)을 따른다.
4. Git이 없거나 원문이 커밋되지 않았으면 허가된 보존이 끝날 때까지 내용을 지우지 않는다. 이 정리를 위해 자동으로 Git을 초기화하거나 커밋·push하지 않는다.
5. 보존이 확인되면 완료한 작업 목록과 다음 작업 등 지난 본문을 비우되 파일과 INDEX 링크는 유지한다. `상태: 완료`, `현재 진행 중인 작업 없음`을 남긴다. 다음 작업을 시작할 때 같은 파일을 진행 중으로 갱신한다. 정리·재사용에 따른 내용 변경도 해시 비교로 감지한다.

완료 정리 후의 예:

```markdown
# 현재 작업 상태

상태: 완료
현재 진행 중인 작업 없음
```

상태 확인 요청만으로 갱신·완료 정리·구현을 수행하지 않는다. 미래 세션의 실행 범위는 현재 사용자의 요청에서 확인한다.

해시 계산의 동작 근거: [git hash-object](https://git-scm.com/docs/git-hash-object).
