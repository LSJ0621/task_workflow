# STATUS 생성·갱신·완료 정리

진행 상황을 여러 작업·세션에 걸쳐 지속적으로 보존할 필요가 있을 때 사용한다. 단발성 문서 정리마다 만들지 않는다.
기존 기록 위치를 우선하고 없으면 `docs/work-notes/`를 후보로 한다. 프로젝트 기록 루트의 STATUS 하나를 사용하고 INDEX에서 연결하며, 작업·세션마다 별도 파일을 만들거나 기존 파일을 임의로 이동하지 않는다.

## 내용과 갱신

현재 단계, 완료한 주요 작업, 다음 작업, 진행을 막는 항목과 주제 문서 링크를 짧게 유지한다.
긴 작업 일지·기획서 복사본·미정 정책의 상세 목록으로 만들지 않는다.

```markdown
# 현재 작업 상태

상태: 진행 중
현재 단계: 예약 입력 검증 구현
완료한 주요 작업: 요청 형식 합의
다음 작업: 오류 응답 검증
진행을 막는 항목: 없음
관련 문서: [예약 정책](booking-policy.md)
```

- 중요한 진행 변화나 다른 세션에 영향을 주는 요구사항·정책·결정·검증 기준 변경 시 갱신한다. 상세는 주제 문서에, STATUS에는 짧은 변경 요약과 해당 문서·절의 링크를 둔다. 구현 진척이 없는 문서 변경도 필요한 알림을 누락하지 않는다.
- 저장 전 최신 상태 확인은 [공통 읽기 규칙](reading.md)의 STATUS 확인 절차를 따른다. 다른 세션의 변경을 보존하고 충돌 시 작성자를 조정한다. 저장 후에는 기록한 내용에 대응하는 해시로 세션의 기억을 갱신한다.
- 수동 변경 번호·계산한 해시·읽음 표시를 문서나 별도 파일에 저장하지 않는다. 기존 수동 번호는 허가된 기록 수정 시 내용 보존을 확인하며 제거한다. STATUS의 읽기·변경 확인만 요청받으면 생성·갱신·완료 정리를 수행하지 않는다.

## 완료와 재사용

1. 현재 추적하는 작업 전체에 미완료 작업·필요한 검증·미해결 장애가 없을 때 완료로 표시한다. 이번 요청이나 한 단계만 끝난 경우, 대기·중단·실패를 전체 완료로 처리하지 않는다.
2. 이후에도 필요한 결정·근거·검증 결과를 주제 문서에 보존하고 링크를 확인한다. 지난 내용을 비우기 전의 원문 보존 확인과 커밋 권한 판단은 [Git 이력 규칙](history.md)의 원문 정리·커밋 절을 따른다. Git이 없거나 원문이 커밋되지 않았으면 허가된 보존이 끝날 때까지 지우지 않는다.
3. 보존이 확인되면 완료한 목록·지난 다음 작업 등을 비우고 아래 최소 내용과 파일·INDEX 링크를 유지한다. 다음 작업은 같은 파일을 진행 중으로 갱신한다.

```markdown
# 현재 작업 상태

상태: 완료
현재 진행 중인 작업 없음
```

이 정리만을 위해 자동으로 Git을 초기화하거나 커밋·push하지 않는다.
