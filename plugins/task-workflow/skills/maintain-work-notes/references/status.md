# STATUS 읽기·갱신·완료 정리

## 위치와 형식

기존 기록 관례와 사용자가 지정한 경로를 우선한다. 새로 필요하면 프로젝트의 기록 루트에 `STATUS.md` 하나를 두고 INDEX에서 연결한다. 작업·세션마다 별도 STATUS를 만들지 않는다. 기존 파일은 임의로 이동하지 않는다.

첫 줄은 양의 정수인 `revision: N`으로 유지한다. 초기 번호는 1이며, 본문을 변경하는 저장 단위마다 최신 번호에서 1 증가시켜 본문과 함께 저장한다. 읽기만 하거나 내용이 그대로이면 번호를 올리지 않는다.

```markdown
revision: 12
# 현재 작업 상태

상태: 진행 중
현재 단계: 예약 입력 검증 구현
완료한 주요 작업: 요청 형식 합의
다음 작업: 오류 응답 검증
진행을 막는 항목: 없음
관련 문서: [예약 정책](booking-policy.md)
```

본문은 진행에 필요한 요약과 링크만 유지한다. 상세 요구·결정·미정 정책·검증 근거는 주제별 문서에 둔다.

## 필요한 부분만 읽기

- 새 세션·재개·compact 후 본문이나 마지막 번호를 기억하지 못하면 본문을 읽고 `(경로, revision)`을 세션별로 기억한다. 다른 세션이 읽었다는 것을 자신의 읽기 완료로 취급하지 않는다.
- 이후 상태 공유 중인 세션에서는 각 요청 처리 전 `head -n 1 <STATUS 경로>` 또는 동등한 부분 읽기로 첫 줄만 확인한다. 같은 경로·같은 번호이고 읽은 본문을 기억하면 재사용하고, 번호가 다르면 본문을 다시 읽는다. 번호가 낮아졌어도 변경으로 취급한다.
- 경로 변경, 번호 누락·잘못된 형식, 알려진 내용 불일치는 본문을 다시 확인한다. 기존 번호 없는 문서는 읽을 수 있으며, 허가된 기록 갱신 시에만 번호를 도입한다. 파일이 없거나 읽기에 실패하면 이전 상태를 최신이라고 단정하지 않는다.
- 변경 번호는 STATUS의 변경만 나타낸다. 코드나 다른 문서의 변경 감지·동시 편집 잠금으로 간주하지 않는다. 작업에 필요한 주제 문서·코드는 해당 작업 범위에서 읽는다.

## 갱신과 완료

1. 중요한 진행 변화가 생기면 관련 내용만 갱신한다. 저장 직전 최신 파일을 다시 읽어 다른 세션의 변경을 보존하고 그 번호에서 증가시킨다. 충돌이 드러나면 같은 문서의 작성자를 조정한다. 전역 '읽음' 표시로 변경 번호를 초기화하지 않는다.
2. 현재 추적 중인 작업 전체에 미완료 작업·필요한 검증·미해결 장애가 없을 때 `상태: 완료`로 표시한다. 이번 요청이나 한 단계가 끝났어도 후속 작업이 남으면 진행 중으로 유지한다. 대기·중단·실패를 완료로 처리하지 않는다.
3. 완료한 내용을 비우기 전에 이후에도 필요한 결정·근거·검증 결과를 주제 문서에 보존하고 링크를 확인한다. 덜어낼 과거 상태 원문이 실제 Git 커밋의 해당 경로에 포함되는지도 확인한다. 보존·커밋 권한 판단은 [Git 이력 규칙](history.md)을 따른다.
4. Git이 없거나 원문이 커밋되지 않았으면 허가된 보존이 끝날 때까지 내용을 지우지 않는다. 이 정리를 위해 자동으로 Git을 초기화하거나 커밋·push하지 않는다.
5. 보존이 확인되면 완료한 작업 목록과 다음 작업 등 지난 본문을 비우되 파일과 INDEX 링크는 유지한다. `상태: 완료`, `현재 진행 중인 작업 없음`을 남기고 변경 번호를 증가시킨다. 다음 작업을 시작할 때 같은 파일을 진행 중으로 갱신하며 번호를 계속 증가시킨다.

완료 정리 후의 예:

```markdown
revision: 14
# 현재 작업 상태

상태: 완료
현재 진행 중인 작업 없음
```

상태 확인 요청만으로 갱신·완료 정리·구현을 수행하지 않는다. 미래 세션의 실행 범위는 현재 사용자의 요청에서 확인한다.
