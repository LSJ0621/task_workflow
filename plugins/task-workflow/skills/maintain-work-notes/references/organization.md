# 문서 구조와 참조 규칙

## 문서 역할과 기록 내용

기존 기록의 위치·현재 상황을 먼저 파악해야 하면 [공통 읽기 규칙](reading.md)을 적용한다. 아래는 허가된 작성·정리에 필요한 규칙이다.

| 위치 | 소유하는 내용 |
| --- | --- |
| INDEX | 문서별 상대경로 링크·목적·다루는 범위·읽어야 할 상황만 안내하는 목차 |
| STATUS | 필요한 경우 현재 작업 진행의 짧은 요약과 주제 문서 링크 |
| 주제별 문서 | 요구사항·확정 정책·결정 이유·미정 항목의 상세와 증거 |
| 프롬프트 | 이번 세션의 구체적인 요청·추가 지시 |

- 사용자 요구·채택된 결정, 에이전트 제안·임시 가정, 미해결 쟁점을 구분한다. 중요한 결정의 이유·근거와 변경 시 이전 결정·변경 이유를 보존한다. 의견 충돌을 임의로 합의된 것으로 기록하지 않는다.
- 구현됨·검사됨·계획됨을 구분한다. 실행하지 않은 검증이나 관찰하지 않은 결과를 성공으로 적지 않는다.
- 중요한 결정·단계 전환·인계 전·기록 요청 시 관련 변경만 반영한다. 매 메시지마다 모든 문서를 다시 쓰거나 대화 전체를 복제하지 않는다.
- 지속적인 진행 정보를 프롬프트에만 의존하지 않고, 문서에 옮긴 과거 요청을 현재 실행 허가로 취급하지 않는다. 원문 보존 요구·제출 양식을 우선하고 압축 과정에서 수치·인터페이스·제출 조건·결정 상태를 바꾸지 않는다.
- 원문 축약·제거와 과거 결정의 보존 경계는 [Git 이력 규칙](history.md)에 따른다. 다른 세션에 영향을 주는 진행 정보의 생성·갱신 판단은 아래 [진행 기록](#진행-기록)을 따른다.

## 파일·폴더 판단

| 작업 | 기준 |
| --- | --- |
| 기존 문서에 추가 | 같은 질문을 다루며 함께 읽어야 의미가 통하는 내용 |
| 별도 파일로 분리 | 독립적인 조회·수정 목적이 있고 다른 내용까지 읽을 필요가 없는 주제 |
| 하위 폴더 생성 | 관련 문서들이 여러 개 생겼고 안정적인 공통 주제로 묶으면 탐색 범위를 줄일 수 있음 |
| 과거 원문 정리 | 현재 문서에는 중요한 결정 요약·이유를 유지하고, 상세 원문은 실제 보존 상태에 따라 Git 출처 또는 기존 보존 문서로 연결 |

줄 수·파일 수만으로 나누지 않는다. 같은 역할·주제의 문서가 분리 후에도 항상 함께 있어야 의미가 통한다면 한 문서가 적합하다. 이 판단으로 INDEX·STATUS·주제별 문서의 역할을 다시 합치지 않는다.
중복 문서가 조금 생겼다는 이유로 전체 폴더를 재편하지 않는다. 현재 탐색 문제를 해결하는 최소 변경을 한다.
주제 이름은 문서 내용에서 도출한다. 데이터·API·의사결정 같은 폴더를 빈 상태로 미리 생성하지 않는다.
코드·데이터·외부 제출물을 문서 정리의 일부로 임의 이동하지 않는다.
과거 원문을 축약하거나 분할·병합해 출처가 모호해질 때는 [이력 읽기·보존·커밋 규칙](history.md)도 확인한다. 별도 과거 문서 폴더를 일괄 생성하지 않는다.

## INDEX

루트와 하위 폴더의 INDEX는 문서 안내 목차로만 사용한다. 다음처럼 문서별 상대경로 링크·목적·다루는 내용·읽어야 할 상황을 안내한다. 표 모양은 기존 관례에 맞춰도 된다.

| 문서 | 목적 | 다루는 내용 | 언제 읽는가 |
| --- | --- | --- | --- |
| 상대경로 링크 | 문서가 필요한 이유 | 주제·범위의 안내 | 이 문서가 답할 수 있는 질문 |

문서가 무엇을 다루는지 소개하되 서비스 정의·확정 정책·결정 내용·현재 단계 자체를 요약하지 않는다. 진행 상태·다음 작업·미해결 쟁점의 상세 내용·새 세션의 작업 순서나 지시는 INDEX에 넣지 않는다. 짧다는 이유로 예외를 두지 않는다.
INDEX는 STATUS와 주제별 문서의 현재 위치를 안내하고 과거 버전 전체를 나열하지 않는다.
하위 폴더의 문서 목록이 루트 INDEX를 과도하게 늘리면 해당 폴더에 INDEX를 두고 루트에서 연결한다.
모든 폴더에 기계적으로 INDEX를 만들지 않는다. 모든 문서는 루트 INDEX에서 직접 또는 하위 INDEX를 통해 찾을 수 있게 한다.

## 진행 기록

허가된 기록 작성·정리에서 인계·단계 전환 등으로 현재 상태와 다음 작업을 이후 작업·세션에 보존해야 하면, STATUS가 아직 없어도 [STATUS 관리](status.md)를 읽어 생성·갱신·완료 정리를 수행한다. STATUS가 없다는 이유로 진행 정보를 주제 문서나 AGENTS.md에 대신 기록하지 않는다.
단발성 정리에서는 빈 STATUS를 만들지 않는다. 읽기·검토 요청만으로 STATUS를 생성·갱신하지 않는다.

## 참조 작성

- 문서 간에는 상대경로 Markdown 링크를 사용한다. 표기에는 읽는 이유나 확인할 내용을 적는다.
- 특정 부분만 필요하면 제목 앵커를 연결한다. 제목을 바꿀 때 해당 앵커의 참조도 갱신한다.
- 경로만 나열하거나 '관련 자료' 같은 불명확한 링크를 반복하지 않는다.
- 상세 결정·규격은 대표 문서 한곳에서 관리한다. 다른 문서에는 필요한 요약과 대표 문서 링크를 둔다.
- 파일·함수·API처럼 코드 근거를 연결할 때는 저장소 상대경로와 심볼 이름을 같이 적는다. 줄 번호만으로 참조하지 않는다.
- 외부 근거에는 원래 URL을 남긴다. 비공개 자료를 새로운 공개 URL이나 외부 서비스에 복제하지 않는다.
- 분할·병합이나 대폭 수정으로 이전 출처를 찾기 어려워지면 관련 현재 문서에 이동 전 실제 커밋 SHA·당시 저장소 상대경로·절 또는 결정 ID를 연결한다. 현재 문서 링크와 과거 Git 출처를 구분한다.

## 구조 변경 절차

1. 공통 읽기 규칙으로 대상 기록을 파악하고 각 정보의 현재 위치와 이동할 문서를 확인한다.
2. INDEX에 섞인 진행 요약은 필요한 STATUS로, 기획·정책·결정 이유·미정 사항의 상세는 해당 주제 문서로 분리한다. 이미 같은 내용이 있으면 중복 작성하지 않고 대표 위치를 확인한다.
3. 작업 지시 형태의 문장에서도 보존해야 할 기존 합의·미완료 작업·전제 정보를 누락하지 않는다. 현재 프롬프트에 없는 실행 허가를 승계하지 않고, 남겨야 할 원래 맥락은 필요에 따라 주제 문서 또는 확인된 Git 출처로 보존한다.
4. 덜어낼 원문이 실제 커밋에 포함되는지 확인한다. 없다면 허가된 커밋 또는 로컬 원문 보존을 먼저 수행한다. 분리할 독립 주제와 대표 문서를 정하고 의미·결정 상태·보존 요구를 유지하며 이동한다.
5. 이동 전후의 필요한 정보·수치·결정 상태·미정 상태를 대조하고 보존 위치 또는 확인된 과거 출처로 찾을 수 있는지 확인한다. INDEX는 목차만 담고, STATUS와 각 주제 문서를 적절하게 연결한다.
6. INDEX와 역참조를 갱신하고 기록 루트에서 이전 경로와 제목 앵커를 검색해 수정한다. 이동한 파일의 로컬 링크·앵커와 기록한 Git 출처가 실제로 조회되는지 확인한다.
7. 커밋이 허가된 작업이면 정리 단위로 확정하되 가능하면 내용 변경과 구조 변경을 분리한다.

기록 요청 범위를 벗어난 대규모 재편이나 내용 삭제가 필요하다면 그 변경을 먼저 제안한다.
기록된 결정을 바꾸는 것과 문서 위치를 바꾸는 것을 혼동하지 않는다.
