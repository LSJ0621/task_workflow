# 문서 구조와 참조 규칙

## 파일·폴더 판단

| 작업 | 기준 |
| --- | --- |
| 기존 문서에 추가 | 같은 질문을 다루며 함께 읽어야 의미가 통하는 내용 |
| 별도 파일로 분리 | 독립적인 조회·수정 목적이 있고 다른 내용까지 읽을 필요가 없는 주제 |
| 하위 폴더 생성 | 관련 문서들이 여러 개 생겼고 안정적인 공통 주제로 묶으면 탐색 범위를 줄일 수 있음 |
| 과거 기록 분리 | 현재 판단에서는 읽을 필요가 줄었지만 변경 전 결정과 근거를 보존해야 함 |

줄 수·파일 수만으로 나누지 않는다. 분리 후 항상 같이 읽어야 한다면 한 문서가 적합하다.
중복 문서가 조금 생겼다는 이유로 전체 폴더를 재편하지 않는다. 현재 탐색 문제를 해결하는 최소 변경을 한다.
주제 이름은 문서 내용에서 도출한다. 데이터·API·의사결정 같은 폴더를 빈 상태로 미리 생성하지 않는다.
코드·데이터·외부 제출물을 문서 정리의 일부로 임의 이동하지 않는다.

## INDEX

루트 INDEX에는 짧은 현재 상태와 다음과 같은 탐색 표를 둔다. 이름과 표 모양은 기존 관례에 맞춰도 된다.

| 문서 | 내용 | 언제 읽는가 |
| --- | --- | --- |
| 상대경로 링크 | 다루는 범위와 현재·과거 상태 | 이 문서가 답할 수 있는 질문 |

중요한 최신 결정은 상세 근거가 있는 한 문서로 연결한다.
현재 상태가 길어지면 작업 상태 문서로 분리하고 INDEX에는 요약과 링크만 남긴다.
하위 폴더의 문서 목록이 루트 INDEX를 과도하게 늘리면 해당 폴더에 INDEX를 두고 루트에서 연결한다.
모든 폴더에 기계적으로 INDEX를 만들지 않는다. 모든 문서는 루트 INDEX에서 직접 또는 하위 INDEX를 통해 찾을 수 있게 한다.

## 참조 작성

- 문서 간에는 상대경로 Markdown 링크를 사용한다. 표기에는 읽는 이유나 확인할 내용을 적는다.
- 특정 부분만 필요하면 제목 앵커를 연결한다. 제목을 바꿀 때 해당 앵커의 참조도 갱신한다.
- 경로만 나열하거나 '관련 자료' 같은 불명확한 링크를 반복하지 않는다.
- 상세 결정·규격은 대표 문서 한곳에서 관리한다. 다른 문서에는 필요한 요약과 대표 문서 링크를 둔다.
- 파일·함수·API처럼 코드 근거를 연결할 때는 저장소 상대경로와 심볼 이름을 같이 적는다. 줄 번호만으로 참조하지 않는다.
- 외부 근거에는 원래 URL을 남긴다. 비공개 자료를 새로운 공개 URL이나 외부 서비스에 복제하지 않는다.

## 구조 변경 절차

1. INDEX와 관련 문서의 필요한 부분을 읽어 현재 소유 문서와 중복·탐색 문제를 확인한다.
2. 분리할 독립 주제와 대표 문서를 정하고, 기존 의미·결정 상태·원문 보존 요구를 유지하며 이동한다.
3. INDEX를 갱신하고 기록 루트에서 이전 경로와 제목 앵커를 검색해 역참조를 수정한다.
4. 이동한 파일이 기록 루트 안에 있는지, 로컬 파일 링크와 제목 앵커가 유효한지 확인한다. 파일 밖 링크는 읽기 권한 안에서 확인한다.
5. 현재·과거 결정이 혼동되지 않는지, 중요 근거가 유실되지 않았는지 확인한다.

기록 요청 범위를 벗어난 대규모 재편이나 내용 삭제가 필요하다면 그 변경을 먼저 제안한다.
기록된 결정을 바꾸는 것과 문서 위치를 바꾸는 것을 혼동하지 않는다.
