# 프로젝트 지침 설정

프로젝트에서 계속 적용할 핵심 지침과 실제 문서 진입점을 짧게 구성한다.
과제 분석이나 프로젝트 기록 작성을 대신하지 않는다.

## 확인과 초안

1. 대상 프로젝트와 기존 AGENTS 지침을 확인한다. 사용자 지정 자료, README·실행 설정·기존 기록에서 필요한 부분만 읽고 경로·명령·확정된 제약의 근거를 파악한다. 대상이 불분명할 때만 확인한다.
2. [AGENTS 작성·연결 기준](references/project-guidance.md)에 따라 지침을 선별한다. 사용자 지시·자료에서 확인한 사실·에이전트 제안을 구분하고 확인되지 않은 정책·기술 선택을 확정하지 않는다.
3. 기존 지침을 보존한 AGENTS 초안과 추가·변경 이유, 근거 위치를 채팅으로 제시한다. 지침 작성에 필요한 미정 항목만 질문으로 남기며 업무 정책을 결정하는 분석·설계 대화로 넓히지 않는다. 모든 항목을 기계적으로 채우거나 긴 배경 설명을 붙이지 않는다.

기본은 초안 제안까지다. 사용자가 검수할 초안을 별도 파일로 저장하거나 대상 AGENTS를 먼저 수정하지 않는다.
일반적인 설정 요청만으로 제품 코드·기획 문서·INDEX·STATUS·기술스택 문서를 생성·수정하거나 애플리케이션 테스트·빌드·의존성 설치를 시작하지 않는다.

## 검수 후 반영

- 사용자가 검수한 초안 또는 직접 확정한 문구를 반영하도록 요청하면 해당 범위에서 AGENTS를 작성·갱신한다. 이미 검수한 내용을 다시 승인받지 않는다.
- 적용 직전 기존 파일과 지침을 다시 확인한다. 다른 작업의 변경을 보존하고 승인되지 않은 새 규칙을 끼워 넣지 않는다.
- 실제 문서 링크, 기존 지침 보존, 중복·충돌, 상세 절차의 불필요한 복사 여부를 확인한다. 관련 환경에서 요청된 연결 파일도 같은 기준으로 확인한다.
- 변경 위치와 주요 지침·남은 미확인 항목만 짧게 보고한다. 설정 문구 작성만으로 스킬 자동 선택이나 compact 후 자동 복구가 검증됐다고 말하지 않는다.

프로젝트 적용은 해당 프로젝트 안으로 제한한다. 사용자 전역 설정·다른 프로젝트·설치된 플러그인은 변경하지 않는다. 커밋·push는 별도로 부여된 권한을 따른다.
