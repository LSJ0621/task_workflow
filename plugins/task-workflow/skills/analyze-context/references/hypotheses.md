# 추정 기록

자가 발전 순서의 7단계에서 읽는다. 규칙을 넣거나 고칠 때마다 무엇을 원인으로 봤는지 적어 두는 방법이다.
추정을 적어 두지 않으면 다음 실행이 그 추정이 맞았는지 판단할 수 없다. 문장만 덧붙이게 된다.
고친 이유를 남기는 곳은 둘이다. 커밋 메시지와 이 기록이다. 따져 본 다른 방법과 대어 본 지난 사례는 커밋 메시지에 적는다.

## 파일

| 파일 | 담는 것 |
| :- | :- |
| 지식 베이스 `evolve/hypotheses.md` | 지켜보는 중인 추정. 규칙 절 하나에 묶음 하나 |
| 지식 베이스 `evolve/hypotheses-archive.md` | 끝난 시도(틀림, 맞음). 물을 때만 읽는다 |

둘 다 지식 베이스 main에 커밋한다. 원본에서 다시 만들 수 없는 파일이라 지우거나 다시 만들지 않는다. 파일이 없으면 아래 머리글로 만든다.

```markdown
# 추정 기록

자가 발전(`task-workflow:analyze-context`)이 규칙을 넣거나 고칠 때마다 무엇을 원인으로 봤는지 적는다.
규칙 절 하나에 묶음 하나다. 끝난 시도는 `hypotheses-archive.md`에 있다.

## <파일> — <절 이름>
- 2025-01-02 틀림: <원인으로 본 것과 바꾼 것, 한 줄> (<저장소 이름> <커밋 해시>)

### 2025-01-08 <무엇을 어떻게 고쳤나, 한 줄>
- 상태: 지켜보는 중
- 원인: <무엇이 없어서 또는 무엇이 안 읽혀서 났다, 한 문장> (C-…)
- 바꾼 것: 원래 "<고치기 전 문장. 없었으면 '없음'>" → 고친 뒤 "<고친 문장>"
- 커밋: <저장소 이름> <커밋 해시>
- 판정 조건: <무엇이 보이면 이 시도가 틀린 것인가>
```

- **묶음**은 규칙 절 하나에 하나다. 제목은 `## <파일> — <절 이름>`이다. 같은 절을 다시 고치면 새 묶음을 만들지 않고 그 묶음에 시도를 더한다. 같은 절을 몇 번 고쳤는지가 여기서 보인다.
- **시도**는 묶음 안에 날짜순으로 쌓는다. 제목은 `### YYYY-MM-DD <한 줄>`이다. 다른 문서는 시도를 묶음 제목과 날짜로 가리킨다.
- **상태**는 셋 중 하나다.
  - `지켜보는 중`: 넣은 뒤 아직 맞는지 모른다.
  - `틀림 (YYYY-MM-DD)`: 판정 조건에 걸렸다. 자가 발전이 바꾼다.
  - `맞음 (YYYY-MM-DD)`: 토요일 점검이 정한다. 자가 발전은 이 값으로 바꾸지 않는다.
- **원인**에는 근거 사례 id를 붙인다. 사용자 말을 옮길 때는 사례의 `## 있었던 일`에 있는 말만 그대로 옮긴다. 사용자가 대화 중에 정해서 넣은 변경은 "사용자가 정함"과 사용자 말을 적는다.
- **판정 조건**은 측정값(`evolve/metrics.md`의 열)이나 사례의 도구 목록으로 확인할 수 있는 것을 먼저 쓴다. 사용자 지적만으로 판정하는 조건은 다른 방법이 없을 때만 쓴다. 사례 한 건이나 숫자 하나를 보고 걸렸다 아니다를 가를 수 있게 적는다. "효과가 없으면"처럼 가를 수 없는 말을 쓰지 않는다.
  - 측정값으로 확인하는 조건이면 상태 파일 "지켜보는 측정값" 절에도 한 줄 옮긴다(자가 발전 스킬 "상태 파일" 절). 메인 세션이 그 절로 새벽 3단계를 돌릴지 정한다.
- **끝난 시도**(틀림, 맞음)는 자가 발전이 실행 때 `hypotheses-archive.md`로 옮긴다. 같은 묶음 제목 아래에 시도를 통째로 붙인다. 원래 묶음에는 위 예의 첫 줄처럼 한 줄 요약만 남긴다. 상태 파일 "지켜보는 측정값"에 그 시도의 줄이 있으면 지운다.
- 옮기는 것 말고는 적은 줄을 고치지 않는다. 고치는 것은 상태 줄뿐이다.
