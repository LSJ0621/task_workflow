# 만들기 단계: HTML과 태그

점검 보고의 마지막 단계다. 초안과 판정으로 HTML 보고서를 만들어 지식 베이스에 올리고, 세 저장소에 점검 태그를 단다.
이 단계를 맡은 서브에이전트는 이 파일, 같은 폴더의 `draft.md`, 틀 `../assets/report-template.html`, 사서의 [글쓰기 규칙](../../librarian/references/writing.md)을 읽는다. `analyze.md`와 `verify.md`는 읽지 않는다.

받는 것: 초안과 판정의 경로(`/tmp/review-report-<보고서 날짜>/draft.md`, `verdict.md`).
내는 것: 지식 베이스 `raw/reviews/<보고서 날짜>.html`과 그 커밋, 세 저장소의 태그.

## 4. HTML 만들기

1. **초안에 판정을 입힌다.** 번호마다 판정을 본다.
   - `맞음`: 그대로 싣는다.
   - `틀림`: 뺀다. 틀린 줄을 사용자가 읽고 판단하면 안 되기 때문이다.
   - `확인 못 함`: 싣되 "확인 못 함" 표시를 붙인다.
   - 판정이 없는 번호는 `확인 못 함`으로 본다.
   - 줄을 빼서 절이 비면 "없음"으로 둔다.
   - 초안의 내용을 고쳐 쓰거나 새 줄을 더하지 않는다. 이 단계는 근거를 다시 열지 않으므로, 여기서 더한 말은 검증되지 않은 말이 된다.
2. **틀을 채운다.** `report-template.html`을 복사해 `{{…}}` 자리를 채우고, "반복" 주석이 붙은 덩어리를 줄 수만큼 되풀이한다. 채운 뒤 주석과 남은 `{{…}}`를 지운다.
   - 틀의 절 순서를 바꾸지 않는다. "사용자가 정할 것"과 "사용자가 볼 것"이 맨 위다. 사용자는 이 둘만 보고 닫아도 되게 한다.
   - 변경 흐름은 초안의 줄마다 틀의 도식 덩어리(무슨 일이 있었나 → 무엇을 바꿨나 → 어디에 넣었나) 하나로 그린다.
   - 맨 위의 "에이전트가 썼다"는 알림 문장은 지우지 않는다(사서 `records.md` "점검 보고서" 절).
   - 줄마다 근거를 작은 글씨로 그대로 싣는다.
   - 끝의 검증 줄에 초안 줄 수, 맞음, 확인 못 함, 틀려서 뺀 줄 수를 적는다.
3. **HTML 규칙을 지킨다.**
   - 파일 하나다. CSS와 SVG는 파일 안에 넣는다.
   - 외부 자원을 불러오지 않는다. 글꼴, 스타일, 스크립트, 그림을 밖에서 가져오지 않는다. 지식 베이스만 받아도, 인터넷이 없어도 열려야 해서다. PR 주소처럼 눌러서 가는 링크는 괜찮다.
   - 밝은 화면과 어두운 화면 둘 다에서 읽힌다. 틀의 색 변수를 그대로 쓴다. 색을 새로 정하면 두 화면 값을 같이 넣는다.
   - 글자로 쓰는 내용에 `<`, `>`, `&`가 있으면 `&lt;`, `&gt;`, `&amp;`로 바꾼다.
   - 글은 사서의 글쓰기 규칙을 따른다.
4. **확인한다.**
   ```bash
   grep -nE '\{\{|<link|<script|@import|url\(|src=' <보고서 파일>    # 아무것도 안 나와야 한다
   ```
   초안에서 `맞음`과 `확인 못 함`인 번호 수와 보고서에 실린 줄 수가 맞는지도 센다.
5. **지식 베이스에 올린다.**
   - 파일 이름은 `raw/reviews/<보고서 날짜>.html`이다. 같은 이름이 이미 있으면 덮어쓰지 않고 `<보고서 날짜>-2.html`로 쓴다. 원본 폴더는 추가만 해서다.
   - main에서 `git pull --ff-only`(안 되면 `git pull --rebase`)를 한 뒤 그 파일만 커밋하고 push한다. 메시지는 "점검 보고 YYYY-MM-DD: 정할 것 n, 볼 것 n".
   - push가 거부되면 `git pull --rebase origin main`을 한 번 하고 다시 push한다. 그래도 안 되면 커밋만 남기고 보고한다.

## 5. 태그 달기

보고서 커밋이 끝난 뒤에 단다. 보고서 없이 태그만 앞서 가면 그 사이의 변경이 어느 보고서에도 실리지 않는다.

```bash
git -C <저장소> tag review-<보고서 날짜> <초안 머리에 적힌 그 저장소의 끝 커밋>
```

- 세 저장소 모두에 단다. 끝 커밋은 초안 머리의 `claude`, `plugin`, `kb` 줄에 있다. 지금의 HEAD가 아니라 그 커밋에 단다. 분석이 끝난 뒤 들어온 커밋을 다음 점검이 놓치지 않게 하기 위해서다.
- 로컬에만 단다. 태그는 push하지 않는다.
- 같은 이름의 태그가 이미 있으면 옮기지 않는다. `review-<보고서 날짜>-2`로 단다.

## 보고

두 줄.
- **완료**: 보고서 파일 경로와 커밋 해시, push 여부. "사용자가 정할 것" n건, "사용자가 볼 것" n건. 틀려서 뺀 줄 n, 확인 못 함 n. 저장소마다 단 태그 이름과 커밋.
- **확인할 것**: "사용자가 정할 것"이 있으면 건수. push나 태그가 안 된 저장소. 없으면 "없음".

## 하지 말 것

- 초안에 없는 내용을 보고서에 넣지 않는다.
- 이미 올린 보고서를 고치지 않는다.
- 보고서 파일 말고 다른 파일을 커밋하지 않는다.
- 태그를 옮기거나 지우거나 push하지 않는다.
- 규칙을 고치지 않는다.
- 다른 서브에이전트를 부르지 않는다.
