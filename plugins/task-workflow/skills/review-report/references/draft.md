# 초안과 판정의 형식

점검 보고의 세 단계(분석, 검증, 만들기)가 주고받는 파일의 형식이다. 세 단계를 맡은 서브에이전트가 모두 읽는다.
단계 사이에는 이 파일들만 오간다. 앞 단계의 생각이나 결론을 말로 넘기지 않는다. 검증이 분석의 결론에 끌려가지 않게 하기 위해서다.

## 임시 폴더

`/tmp/review-report-YYYY-MM-DD/` (보고서 날짜). 저장소 밖이라 커밋되지 않고, 다음 단계가 같은 경로로 찾는다.

| 파일 | 누가 쓰나 | 누가 읽나 |
| :- | :- | :- |
| `draft.md` 초안 | 분석 단계 | 검증 단계, 만들기 단계 |
| `verdict.md` 판정 | 검증 단계 | 만들기 단계 |

보고서 날짜는 메인 세션이 처음에 한 번 정해 모든 단계에 같은 값을 넘긴다. 단계마다 오늘 날짜를 새로 구하면 폴더가 어긋날 수 있어서다.

## 초안 (`draft.md`)

```markdown
# 점검 보고 초안 YYYY-MM-DD

- 보고서 날짜: YYYY-MM-DD
- 지난 점검 태그: review-YYYY-MM-DD (처음에는 review-baseline)
- claude: <전역 설정 저장소 경로> | <태그가 가리키는 커밋>..<끝 커밋>
- plugin: <플러그인 저장소 경로> | <태그가 가리키는 커밋>..<끝 커밋>
- kb: <지식 베이스 경로> | <태그가 가리키는 커밋>..<끝 커밋>

## 요약
- [1] 규칙 추가 2건 | 근거: claude@1a2b3c4, plugin@5d6e7f8
- [2] 규칙 수정 1건 | 근거: claude@2b3c4d5
- [3] 규칙 삭제 0건 | 근거: claude@0a1b2c3..2b3c4d5, plugin@4c5d6e7..5d6e7f8
- [4] 전역 지침 50줄 → 53줄 | 근거: claude@0a1b2c3..2b3c4d5 -- CLAUDE.md
- [5] 응답 양식 40줄 → 40줄 | 근거: claude@0a1b2c3..2b3c4d5 -- output-styles

## 사용자가 정할 것
- [6] 점검 장치: <무엇을 정해야 하나>. 이유: <이유>. 변경안: <변경안> | 근거: state:사용자에게 올릴 것, C-20250101-01

## 사용자가 볼 것
- [7] 또 어김: <한 문장> | 근거: C-20250108-02, claude@1a2b3c4

## 변경 흐름
- [8] 무슨 일: <사례 한 줄> → 무엇을 바꿈: <규칙 한 줄> → 어디에: <파일과 절> | 근거: C-20250101-01, claude@1a2b3c4

## 추정 점검
- [9] 아직 지켜봄: <무엇을 원인으로 보고 무엇을 고쳤나 한 줄>. 넣은 날 2025-01-08. 틀렸다고 볼 신호: <신호> | 근거: hypo:H-20250108-01
- [10] 틀려서 다시 봄: <지난번에 본 원인> → <이번에 본 원인>. 사용자 말: "<그대로>" | 근거: hypo:H-20250102-01, hypo:H-20250108-02, C-20250107-01

## 사용자 분석
- [11] 없음: 이번 기간에 분석 기록이 달라지지 않음 | 근거: kb@3c4d5e6..7f8a9b0 -- raw/context

## 규칙 이력
- [12] <규칙 한 줄> (<파일과 절>): 2025-01-01 생김(사용자), 2025-01-08 고침(자가 발전) | 근거: claude@0a1b2c3, claude@1a2b3c4

## 구조 점검
- [13] 없음: 이번 기간에 구조 변경 없음 | 근거: kb@3c4d5e6..7f8a9b0

## 보류한 후보
- [14] <후보 한 문장>. 보류한 이유: 한 건뿐 | 근거: state:보류한 후보, C-20250105-01
```

- 머리의 다섯 줄은 꼭 채운다. 끝 커밋은 모으기를 시작할 때 그 저장소 main이 가리키던 커밋이다. 만들기 단계가 이 커밋에 태그를 단다.
- **절은 위의 아홉 개이고 순서는 고정이다.** 보고서의 절 목록은 여기에만 둔다. 절마다 무엇을 담는지는 `analyze.md` "2. 분석"에 있다.
- 요약 절에는 위의 다섯 줄(추가, 수정, 삭제, 전역 지침 줄 수, 응답 양식 줄 수)을 이 순서로 꼭 쓴다. 세는 방법은 아래 "세는 기준"이다.
- 내용 줄은 `- [번호] 내용 | 근거: …` 꼴이다. 번호는 문서 전체에서 1부터 차례로 붙인다. 한 줄에는 확인할 수 있는 사실 한 가지만 쓴다.
- 내용이 없는 절에는 `없음:`으로 시작하는 줄을 근거와 함께 둔다. 없다는 것도 검증할 수 있어야 해서다.
- 근거가 없는 줄은 쓰지 않는다.

### 근거 적는 법

| 근거 | 적는 꼴 | 여는 방법 |
| :- | :- | :- |
| 커밋 하나 | `claude@1a2b3c4`, `plugin@…`, `kb@…` | `git -C <경로> show <해시>` |
| 커밋 범위 | `kb@3c4d5e6..7f8a9b0`. 파일을 좁히면 뒤에 `-- <파일>` | `git -C <경로> log <범위> [-- <파일>]`, `git -C <경로> diff <범위> [-- <파일>]` |
| 기록 | `C-…`, `D-…`, `X-…` | 지식 베이스 `raw/`에서 그 id로 시작하는 파일 |
| 상태 파일의 절 | `state:<절 이름>` | 전역 설정 저장소의 `evolve/state.md` |
| 추정 기록의 묶음 | `hypo:H-…` | 전역 설정 저장소의 `evolve/hypotheses.md`에서 그 번호로 시작하는 묶음 |
| 아침 보고서 | `report:YYYY-MM-DD` | 전역 설정 저장소의 `evolve/reports/YYYY-MM-DD.md` |
| 커밋 안 된 변경 | `claude:작업 폴더 <파일>` (저장소 이름은 셋 중 하나) | `git -C <경로> diff -- <파일>`, `git -C <경로> status --short` |

저장소 이름 `claude`, `plugin`, `kb`의 경로는 초안 머리에 있다.

## 세는 기준

분석이 요약의 숫자를 셀 때와 검증이 다시 셀 때 같은 기준을 쓴다. 기준이 다르면 숫자가 맞는지 가릴 수 없어서다.

- **규칙을 바꾼 커밋**: 초안 머리의 범위 안에 있는 커밋 중 아래에 드는 것이다. 머지 커밋은 세지 않는다(`git log --no-merges`).
  - 전역 설정 저장소: 저장소가 추적하는 파일(`git -C <경로> ls-files`)을 바꾼 커밋 전부다. 전역 지침, 응답 양식뿐 아니라 훅, `settings.json`, `bin/`, 예약 작업 지시문도 든다. 상태 파일, 추정 기록, 아침 보고서(`evolve/` 아래)만 바꾼 커밋은 뺀다. 규칙이 아니라 자가 발전이 남기는 기록이라서다.
  - 플러그인 저장소: `plugins/` 아래를 바꾼 커밋이다. manifest의 버전만 올린 커밋은 뺀다.
  - 지식 베이스: 규칙이 없으므로 세지 않는다.
- **추가, 수정, 삭제**: 규칙을 바꾼 커밋 하나가 한 건이다. 바뀐 내용을 읽고 셋 중 하나로 가른다.
  - 추가: 새 규칙 문장이나 새 훅·스크립트가 생겼다.
  - 수정: 있던 문장이나 설정이 바뀌었다.
  - 삭제: 문장이 없어졌거나 반대 뜻으로 바뀌었다.
  - 한 커밋에 여러 가지가 섞였으면 삭제, 추가, 수정 순으로 먼저 맞는 것 하나로 센다.
- **줄 수**: 태그가 가리키는 커밋과 끝 커밋에서 각각 센다. 전역 지침은 `CLAUDE.md`, 응답 양식은 `output-styles/` 아래 파일의 합이다.
  ```bash
  git -C <전역 설정> show <커밋>:CLAUDE.md | wc -l
  git -C <전역 설정> ls-tree -r --name-only <커밋> -- output-styles | while read f; do git -C <전역 설정> show "<커밋>:$f"; done | wc -l
  ```

## 판정 (`verdict.md`)

```markdown
# 점검 보고 판정 YYYY-MM-DD

- [1] 맞음
- [2] 틀림 | 본 것: 수정 커밋은 2b3c4d5, 3c4d5e6 둘이다 | 센 값: 2
- [6] 틀림 | 본 것: <근거가 실제로 말하는 것 한 문장>
- [9] 확인 못 함 | 이유: <한 문장>
```

- 초안의 번호마다 한 줄이다. 빠진 번호가 없어야 한다.
- 값은 `맞음`, `틀림`, `확인 못 함` 셋 중 하나다.
- `틀림`에는 `본 것:`을 꼭 쓴다. 만들기 단계가 이 말을 보고서에 싣는다.
- 요약 절의 숫자 줄이 틀림이면 `센 값:`에 검증이 다시 센 숫자를 쓴다. 줄 수 줄은 `50 → 54`처럼 쓴다.
- `없음:` 줄이 틀림이면 `본 것:`에 검증이 찾은 내용과 그 근거를 쓴다.
