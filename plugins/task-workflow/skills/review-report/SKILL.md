# 점검 보고

자가 발전(`analyze-context` 스킬)은 사용자에게 묻지 않고 규칙을 고친다. 그 대신 사용자가 주 1회 무엇이 바뀌었는지 확인하는 문서가 이 보고서다.
평일에는 사용자가 달라고 할 때 아침 보고서로 그날 고친 것을 본다(자가 발전 스킬). 이 보고서는 한 주를 꼼꼼히 보는 자리다. 한 주 동안 세운 원인 추정 가운데 무엇이 맞았고 무엇이 틀려서 다시 봤는지, 사용자가 바라는 것을 분석한 기록이 달라졌는지도 여기서 본다.
사용자가 변경을 하나하나 검수하지 않아도 되게 하는 것이 목적이다. 그래서 사용자가 정해야 하는 것과 꼭 봐야 하는 것을 맨 위에 두고, 나머지는 훑어볼 수 있게 쓴다.
보고서는 에이전트가 쓴 글이라 틀릴 수 있다. 그래서 쓰는 단계와 확인하는 단계를 서로 다른 서브에이전트가 맡는다.

## 단계

| 단계 | 하는 일 | 지침 파일 | 받는 것 | 내는 것 |
| :- | :- | :- | :- | :- |
| 분석 | 1. 모으기, 2. 분석 | `references/analyze.md` | 보고서 날짜, 지난 점검 태그 이름 | 초안 `draft.md` |
| 검증 | 3. 검증 | `references/verify.md` | 초안 경로 | 판정 `verdict.md` |
| 만들기 | 4. HTML 만들기, 5. 태그 달기 | `references/publish.md` | 초안과 판정 경로 | 보고서 파일, 커밋, 태그 |

- 단계마다 서브에이전트 하나가 맡는다. 서브에이전트는 자기 단계의 지침 파일을 읽고, 그 파일 머리에 적힌 파일만 더 읽는다. 다른 단계의 지침 파일은 읽지 않는다. 특히 검증은 분석이 어떻게 썼는지 모르는 채로 근거만 보고 판정해야 한다.
- 서브에이전트는 다른 서브에이전트를 부르지 못한다. 단계를 차례로 넘기는 것은 메인 세션이 한다. 넘기는 순서, 단계별 모델과 effort, 지난 점검 태그를 찾는 방법, 넘길 때 적을 내용은 `daily-upkeep` 스킬에 있다.
- 메인 세션은 다음 단계에 파일 경로만 넘긴다. 앞 단계가 낸 결론을 말로 옮기지 않는다.
- 단계 사이에 오가는 초안과 판정의 형식, 보고서의 절 목록, 세는 기준, 임시 폴더는 `references/draft.md`에 있다.
- 절마다 무엇을 담는지는 `references/analyze.md` "2. 분석"에, 판정을 보고서에 어떻게 싣는지는 `references/publish.md` "4. HTML 만들기"에 있다.
- 보고서 파일의 형식(HTML, 머리말 없음, 추가만 함, 에이전트가 썼다는 표시)은 사서 `references/records.md` "점검 보고서" 절에 있다.

사용자가 대화에서 "점검 보고 만들어"라고 하면 그 세션이 메인 세션이 된다. `daily-upkeep` 스킬의 "시작할 때 정하는 것"과 "넘기는 방법"대로 점검 보고의 세 단계(6~8단계)만 차례로 넘긴다.
서브에이전트를 쓸 수 없는 환경이면 세 단계를 차례로 직접 하되, 검증 단계에서는 근거를 처음 보는 것처럼 하나씩 다시 연다. 그렇게 했다는 것을 보고에 적는다.

## 사용자가 "점검하자"고 할 때

사용자가 보고서를 읽고 피드백하는 자리다. 새 보고서를 만들지 않는다.

1. 가장 최근 보고서를 연다. 지식 베이스 `raw/reviews/`에서 날짜가 가장 뒤인 HTML 파일이다. 같은 날짜가 여럿이면 번호가 가장 큰 것이다. 맥에서는 `open <파일>`로 브라우저에 띄운다. 열 수 없는 환경이면 파일 경로를 알려 준다.
2. "사용자가 정할 것"이 몇 건인지와 "사용자가 볼 것"이 몇 건인지만 한 문장으로 말한다. 보고서 내용을 대화에 다시 옮기지 않는다. 사용자가 물으면 그 줄의 근거(커밋, 기록)를 열어 답한다.
3. 사용자의 피드백은 `leave-memo` 스킬로 메모한다. 관련 칸에는 보고서 파일 이름(`raw/reviews/YYYY-MM-DD.html`)을 적는다. 다음 자가 발전이 이 표시로 피드백과 보고서를 이어 읽는다.
4. 사용자가 그 자리에서 규칙을 정하거나 "사용자가 정할 것"에 답하면 `analyze-context` 스킬의 "사용자가 대화 중에 규칙을 정했을 때" 절대로 바로 넣는다.
5. 이미 올린 보고서는 고치지 않는다. 보고서가 틀렸다는 피드백도 메모로 남긴다.

## 하지 말 것

- 규칙을 고치지 않는다. 보고서는 있었던 일을 보여 주는 문서다. 고치는 일은 자가 발전이 한다.
- 예약 실행에서는 사용자에게 묻지 않는다.
- 근거 없는 줄을 보고서에 싣지 않는다.
- 비밀값, 자격 정보, 고객 인프라 식별자를 보고서에 적지 않는다. 지식 베이스는 원격 저장소에 올라간다.
- 태그를 push하지 않는다. 점검 태그는 세 저장소에 로컬로만 둔다.
