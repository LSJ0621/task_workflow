# 모으기

매일 정리(`daily-upkeep`) 0단계에서 서브에이전트가 읽는다. 어제까지의 대화 기록에서 사용자가 한 말 네 가지를 골라 지식 베이스에 날짜별 목록으로 쌓는다.
메모는 작업 세션이 남길 때만 생긴다. 메모 없이 지나간 지적과 되물음, 좋다고 한 말, 고른 선택은 대화 기록에만 남는다. 그것을 여기서 모은다.
지금은 쌓기만 한다. 이 목록을 근거로 메모나 기록을 만들지 않고 규칙도 고치지 않는다.

스크립트는 `<스킬 모음 폴더>/analyze-context/scripts/collect_signals.py`다. 후보를 뽑고 목록을 쓰는 일은 스크립트가 하고, 후보를 가르는 일만 직접 한다. 그 밖의 인자는 `--help`에 있다.

## 순서

1. **후보를 뽑는다.** 목록이 없는 날마다 후보 파일이 임시 폴더에 생긴다. 어제까지 7일 안에서 목록이 없는 날이고, 앞서 실패해 빠진 날도 여기에 든다. 후보 파일에는 사용자 글과 앞 답이 들어 있어서 스크립트가 본인만 읽을 수 있게 쓰고, 지난 실행이 남긴 후보 폴더는 이때 지운다.
   ```bash
   python3 "<스킬 모음 폴더>/analyze-context/scripts/collect_signals.py" candidates "<지식 베이스>" --today <오늘 날짜>
   ```
   날마다 `<날짜> | 후보 n건 | <후보 파일>` 한 줄이 나온다. 마지막 줄이 `합계 0일`이면 모을 날이 없다. 그렇게 보고하고 끝낸다.
2. **날마다 후보를 가른다.** 후보는 그날 사람이 친 입력 전부다. 후보마다 앞 답, 사용자 글, 같은 세션의 메모, 이미 있는 메모·기록이 적혀 있다. 아래 넷 가운데 하나에 드는 후보만 고른다.

   | 종류 | 무엇인가 | 여기에 들지 않는 것 |
   | :- | :- | :- |
   | `지적` | 에이전트의 결과, 행동, 판단을 고치거나 틀렸다고 한 말. 에이전트가 낸 방법 대신 다른 방법으로 하라고 한 말도 든다 | 새 일을 시키는 말 |
   | `다시 물음` | 에이전트가 쓴 말이나 한 일을 알아듣지 못해 뜻이나 방법을 되물은 말 | 처음 묻는 질문. 맞는지 확인만 하는 말 |
   | `만족` | 결과를 두고 좋다거나 마음에 든다고 한 말 | 하라는 승인만 있는 말 |
   | `선택` | 에이전트가 내놓은 둘 이상의 선택지 가운데 하나를 고른 말 | 제안 하나에 그러라고 한 말 |

   - 앞 답과 함께 읽고 가른다. 낱말만 보고 가르지 않는다. 둘에 걸치면 표에서 위에 있는 종류로 적는다. 가를 수 없으면 고르지 않는다.
   - "이미 있는 메모·기록"은 스크립트가 찾은 값이다. 그 입력이 어느 기록의 범위 안에 있거나, 같은 세션의 메모가 그 말을 따옴표로 옮겼을 때 채워진다. `없음`인데 "같은 세션의 메모"에 그 말을 두고 적은 메모가 분명히 있으면 `메모 HH:MM`으로 적는다. 분명하지 않으면 스크립트의 값을 둔다.
   - 사용자 글에 자격 정보나 고객 인프라 식별자(계정, 서버·DB 이름, 프로필 이름)가 보이면 `가림`을 붙인다. 스크립트는 모양이 정해진 것(비밀값 모양, 클라우드 자원 id, IP 주소)만 가린다.
3. **가른 결과를 파일로 쓴다.** 후보 파일 옆에 `<날짜>.decisions.md`로 쓴다. 고른 후보만 한 줄씩 적는다. 고를 것이 없는 날도 빈 파일을 쓴다. 그날을 본 것으로 남기기 위해서다.
   ```
   <후보 id> | <지적|다시 물음|만족|선택> [| <없음|메모 HH:MM|기록 id>] [| 가림]
   ```
   셋째 칸을 비우면 스크립트가 찾은 값이 들어간다.
4. **날마다 목록을 쓴다.** 스크립트가 지식 베이스 `evolve/signals/<날짜>.md`를 쓰고, 그날의 후보 파일과 가른 결과 파일을 지운다. 가른 결과 파일을 읽을 수 없으면 종료 코드 1과 함께 어느 줄인지 알려 주고 두 파일을 그대로 둔다. 그 줄을 고쳐 다시 돌린다. 모든 날을 쓰고 나면 후보 폴더가 남지 않아야 한다.
   ```bash
   python3 "<스킬 모음 폴더>/analyze-context/scripts/collect_signals.py" write "<지식 베이스>" --day <날짜> --decisions <가른 결과 파일>
   ```
5. **커밋한다.** 지식 베이스 main에 새 목록 파일만 커밋한다. push하지 않는다. 새벽의 뒤 단계나 메인 세션이 올린다.
   ```bash
   git -C "<지식 베이스>" add evolve/signals
   git -C "<지식 베이스>" commit -m "모으기 <오늘 날짜>: n일, n줄" -- evolve/signals
   ```

## 목록

`evolve/signals/YYYY-MM-DD.md`. 날짜는 그 말이 나온 날이다. 스크립트만 쓰고 손으로 고치지 않는다. 같은 날을 다시 돌리면 덮어쓴다.

```markdown
# 모은 말 2025-01-08

새벽 작업의 모으기 단계가 대화 기록에서 모은 것이다. …
사용자 입력 40건 가운데 3줄. 지적 1(메모·기록 없음 1), 다시 물음 1, 만족 0, 선택 1.

| 시각 | 세션 | 종류 | 사용자 말 | 메모·기록 |
| :- | :- | :- | :- | :- |
| 14:02 | 3f2a9c1e-0b7d-4e55-9a10-6c2d8e4f1b73 | 지적 | 표는 빼라고 했잖아 | 없음 |
```

- 사용자 말은 한 줄로 줄인 첫 80자다. 전문은 세션 id와 시각으로 세션 기록에서 찾는다.
- 메모·기록은 `없음`, `메모 HH:MM`, 기록 id 가운데 하나다. 측정(`measure.py`)이 이 표에서 다시 물어본 횟수와 메모·기록 없는 지적 수를 센다.

## 하지 말 것

- 후보 파일과 대화 기록의 글을 보고, 커밋 메시지, 다른 파일에 옮기지 않는다. 지식 베이스에 남는 것은 목록 파일뿐이다. 후보 파일을 다른 곳에 복사하거나 권한을 바꾸지 않는다.
- 목록 파일을 손으로 쓰거나 고치지 않는다. 가른 결과 파일을 고쳐 다시 돌린다.
- 메모를 남기거나, 기록을 만들거나, 규칙을 고치지 않는다.
- push하지 않는다. 사용자에게 묻지 않는다.

## 보고

- **완료**: 모은 날 수. 날마다 줄 수와 종류별 건수(스크립트가 찍는 요약 줄). 커밋 해시.
- **확인할 것**: 목록을 쓰지 못한 날과 이유. 없으면 "없음".
