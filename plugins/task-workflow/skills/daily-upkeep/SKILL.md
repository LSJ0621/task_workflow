# 매일 정리 순서

예약 작업 하나가 매일 새벽에 떠서 이 순서를 따른다. 메인 세션은 진행만 한다. 단계마다 서브에이전트 하나에 넘기고, 결과를 받아 다음 단계로 간다.
메인 세션은 이 파일만 읽으면 된다. 단계의 내용은 서브에이전트가 자기 지침 파일에서 읽는다.

- 메인 세션이 판단하지 않는 이유: 단계마다 맞는 모델이 다르고, 메인 세션이 내용을 읽기 시작하면 끝까지 갈 컨텍스트가 모자라기 때문이다.
- 작업 하나로 묶은 이유: 예약 작업은 앱이 꺼져 있으면 다음에 켤 때 돈다. 단계를 따로 예약하면 한꺼번에 떠서 순서가 깨진다.
- 사용자가 없는 실행이다. 질문하지 않는다. 정할 수 없는 것은 보고의 "확인할 것"에 적는다.

## 단계

| 순서 | 단계 | 언제 | 서브에이전트에 줄 지침 파일 | `model` | `effort` |
| :- | :- | :- | :- | :- | :- |
| 1 | 사서 정리: 메모를 정식 기록으로 | 매일 | `librarian/SKILL.md`, `librarian/references/shelving.md` | 지정 안 함 | 지정 안 함 |
| 2 | 자가 발전: 사례 분류, 효과 세기, 규칙 고치기 | 매일. 아래 "자가 발전을 건너뛸 때"면 건너뜀 | `analyze-context/SKILL.md` | `fable` | `high` |
| 3 | 구조 점검: 문서를 나눌지 합칠지 판단 | 토요일 | `librarian/SKILL.md`, `librarian/references/structure.md` | `fable` | `high` |
| 4 | 점검 분석: 일주일치를 모아 초안 쓰기 | 토요일 | `review-report/references/analyze.md` | `fable` | `xhigh` |
| 5 | 점검 검증: 초안 줄마다 근거를 다시 열어 확인 | 토요일 | `review-report/references/verify.md` | `opus` | `high` |
| 6 | HTML 만들기, 커밋, 태그 | 토요일 | `review-report/references/publish.md` | 지정 안 함 | 지정 안 함 |

- 지침 파일의 경로는 스킬 모음 폴더(이 스킬 폴더의 한 단계 위) 기준이다. 넘길 때는 절대 경로로 바꿔 준다.
- 단계마다 어느 지침 파일을 주는지는 이 표에만 둔다. 지침 파일이 더 읽으라고 한 파일(형식, 글쓰기 규칙, 저장소 위치 같은 것)은 서브에이전트가 그 파일을 보고 스스로 찾아 읽는다. 메인 세션은 저장소 경로를 몰라도 된다.
- **모델과 effort는 사용자가 정한 값이다.** Claude Code에서는 Agent 도구를 부를 때 `model`과 `effort`를 표의 값 그대로 지정한다. "지정 안 함"인 단계는 두 값을 넣지 않아 기본값으로 돌린다. 표의 값을 다른 값으로 바꾸지 않는다.
- 두 값을 지정할 수 없는 환경이면 지정 없이 돌리고, 어느 단계를 지정 없이 돌렸는지 보고에 적는다.

## 시작할 때 정하는 것

메인 세션이 처음에 한 번 정해 모든 단계에 같은 값을 넘긴다.

1. **오늘 날짜**(`date +%F`). 점검 보고의 보고서 날짜로도 쓴다.
2. **스킬 모음 폴더의 절대 경로.**
3. **지난 점검 태그.** 점검 태그는 세 저장소에 같은 이름으로 달려 있다. 메인 세션은 위치가 정해진 전역 설정 저장소(`~/.claude`)에서 찾는다. 태그를 찾는 명령은 여기에만 둔다.
   ```bash
   git -C ~/.claude tag --list 'review-2*' --sort=-refname | head -1    # 이름이 review-YYYY-MM-DD 인 것 중 가장 뒤
   ```
   아무것도 안 나오면 `review-baseline`이 지난 점검 태그다.
4. **토요일 단계(3~6)를 돌릴지.** 아래 셋 중 하나라도 맞으면 돌린다.
   - 오늘이 토요일이다(`date +%u`가 `6`).
   - 지난 점검 태그가 7일 넘게 지났다. 토요일에 돌지 못했을 때 다음 실행이 대신 돌게 하기 위해서다. 날짜는 태그 이름에서 얻는다. `review-baseline`이면 그 태그가 가리키는 커밋의 날짜를 쓴다(`git -C ~/.claude log -1 --format=%cs review-baseline`).
   - 지시문에 "점검 보고도 돌린다"가 있다. 시험할 때 쓰는 말이다. 요일과 태그를 보지 않고 돌린다.

## 넘기는 방법

단계마다 서브에이전트 하나를 새로 띄운다. 서브에이전트는 메인 세션의 대화를 모르므로 아래를 빠짐없이 적어 준다.

```
목표: <이 단계가 끝나면 무엇이 되어 있어야 하나, 한 문장>
읽을 파일: <지침 파일의 절대 경로>. 이 파일대로 한다. 이 파일이 더 읽으라고 한 파일도 읽는다.
범위: 지침 파일이 정한 일만 한다. 오늘 날짜 <YYYY-MM-DD>. <단계별로 더 주는 것>
완료 기준: <확인할 수 있는 것>
하지 말 것: 사용자에게 묻지 않는다. 다른 서브에이전트를 부르지 않는다. <단계별로 더할 것>
보고: 두 줄(완료 / 확인할 것). 완료 기준을 채우지 못했으면 "확인할 것"에 그렇게 적는다. <단계별로 더 적을 것>
```

단계별로 넣을 내용이다.

| 단계 | 목표 | 더 주는 것 | 완료 기준 | 하지 말 것에 더할 것 |
| :- | :- | :- | :- | :- |
| 1 사서 정리 | 정리 안 된 메모가 정식 기록이 되고 push된다 | 없음 | 정리 절차의 보고가 나오고 불변 조건 점검이 통과한다 | 지침 파일의 "하지 말 것"을 지킨다 |
| 2 자가 발전 | 새 사례가 분류되고, 고칠 규칙이 고쳐져 커밋되고, 상태 파일이 이번 실행 결과와 맞다 | 없음 | 상태 파일이 이번 실행 결과로 고쳐져 있다(달라진 것이 없어 커밋하지 않았어도 완료다). 불변 조건 전체 점검이 통과한다 | 지침 파일의 "바꾸면 안 되는 것"과 "하지 말 것"을 지킨다 |
| 3 구조 점검 | 문서 구조를 분석해 바꿀 것을 바꾸거나 "바꿀 것 없음"으로 끝낸다 | 없음 | 구조 점검 절차의 보고가 나온다 | 지침 파일의 "하지 말 것"을 지킨다 |
| 4 점검 분석 | 보고서 초안이 임시 폴더에 생긴다 | 보고서 날짜(오늘 날짜), 지난 점검 태그 이름 | `/tmp/review-report-<보고서 날짜>/draft.md`가 있고 줄마다 근거가 있다 | 저장소 파일을 고치지 않는다 |
| 5 점검 검증 | 초안의 번호마다 판정이 생긴다 | 초안 경로 | 같은 폴더의 `verdict.md`에 초안의 번호가 모두 있다 | 초안을 고치지 않는다. 지침 파일이 읽지 말라고 한 파일을 읽지 않는다 |
| 6 HTML·커밋·태그 | 보고서가 지식 베이스에 올라가고 세 저장소에 태그가 달린다 | 초안과 판정 경로 | 보고서 커밋이 push되고 태그 세 개가 있다 | 초안과 판정에 없는 내용을 넣지 않는다 |

- 1단계에는 보고에 더 적을 것을 시킨다. "완료 줄 끝에 지식 베이스 `raw/cases/`, `raw/decisions/`, `raw/context/` 각각의 마지막 id를 적는다." 메인 세션이 이 id로 2단계를 건너뛸지 정한다.
- 5단계에는 4단계의 보고 내용을 전하지 않는다. 초안 경로만 준다. 검증이 분석의 결론을 미리 알면 근거를 새로 보지 않게 되기 때문이다.
- 6단계에도 앞 단계의 보고를 옮기지 않는다. 초안과 판정의 경로만 준다.
- 2단계 보고에 플러그인을 다시 설치했다고 나오면 스킬 모음 폴더를 다시 잡는다. 설치 폴더는 버전마다 따로 생겨서, 처음 잡은 폴더에는 고치기 전 지침이 남아 있다. 스킬 모음 폴더에서 두 단계 위(버전 폴더들이 나란히 있는 곳)를 보고 가장 새 버전의 `skills` 폴더를 쓴다. 못 찾으면 처음 잡은 폴더를 그대로 쓰고 보고에 적는다.

## 자가 발전을 건너뛸 때

1단계가 끝난 뒤에 본다. 아래 셋이 모두 맞을 때만 2단계를 건너뛴다. 새로 볼 것이 없는데 큰 모델을 돌리지 않기 위해서다.

- 상태 파일(`~/.claude/evolve/state.md`)이 있다.
- 마지막 실행 뒤에 새 사례(`C-`), 결정(`D-`), 맥락(`X-`)이 하나도 없다. 1단계 보고에 적힌 종류별 마지막 id가 상태 파일 "어디까지 봤나"의 사례, 결정, 맥락 id와 모두 같으면 없는 것이다. 결정과 맥락까지 보는 이유는 사용자가 점검 보고에 한 답이 결정으로 들어오기 때문이다.
- 상태 파일 "판정 못 한 것" 절에 남은 항목이 없다(`- 없음`).

하나라도 확인이 안 되면 돌린다. 건너뛰었으면 보고에 "건너뜀"과 이유를 적는다.

## 멈출 때

앞 단계가 실패하면 뒤 단계를 돌리지 않고 보고로 간다. 뒤 단계는 앞 단계의 결과 위에서 돌기 때문이다.

- 실패: 서브에이전트가 오류로 끝났다. 보고가 없다. 보고에 완료 기준을 채우지 못했다고 적혀 있다.
- 실패가 아닌 것: 2단계를 조건에 따라 건너뜀. 2단계에서 상태 파일이 달라지지 않아 커밋이 없음. 3단계의 "바꿀 것 없음". 5단계에서 틀린 줄이 나옴(6단계가 지침대로 표시해 싣거나 뺀다).
- 실패한 단계를 메인 세션이 대신 하거나 고쳐서 다시 돌리지 않는다. 무엇이 어디서 멈췄는지 적는 것까지가 메인 세션의 일이다.
- 토요일 단계가 중간에 멈추면 태그가 달리지 않는다. 그래서 지난 점검 태그에서 7일이 넘으면 다음 실행이 토요일 단계를 다시 돈다.

## 보고

마지막에 두 줄로 보고한다.

- **완료**: 단계마다 한 줄. `<순서> <단계 이름> | model <값>, effort <값> | <결과 한 문장>` 꼴이다. 값을 지정하지 않았으면 "기본값", 지정할 수 없어 못 넣었으면 "지정 못 함"이라고 적는다. 돌리지 않은 단계는 "건너뜀"이나 "토요일 아님", "앞 단계 실패로 안 돌림"으로 적는다.
- **확인할 것**: 멈춘 단계와 이유. 단계 보고의 "확인할 것"에 있던 것. 자가 발전이 훅이나 점검 스크립트로 올린 것. 점검 보고서가 나왔으면 파일 경로와 "사용자가 정할 것" 건수. 없으면 "없음".

## 하지 말 것

- 메인 세션이 메모를 정리하거나, 규칙을 고치거나, 보고서를 쓰지 않는다. 전부 서브에이전트에 넘긴다.
- 서브에이전트의 결과를 메인 세션이 고쳐 쓰거나 판단을 덧붙이지 않는다.
- 단계 순서를 바꾸거나 여러 단계를 한꺼번에 띄우지 않는다. 한 단계가 끝난 뒤 다음 단계를 넘긴다.
- 사용자에게 질문하지 않는다.
