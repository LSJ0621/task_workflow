# {{REPO_NAME}}

{{OWNER}}의 개인 지식 베이스. 에이전트가 나 대신 판단할 때 읽는 곳이다.
결정과 그 이유, 실수와 거기서 나온 기준, 나와 내 상황에 대한 맥락을 담는다.

## 두 층

| 층 | 폴더 | 성격 | 누가 언제 읽나 |
| :- | :- | :- | :- |
| 원본 | `raw/` | 추가만 한다. 고치지 않는다 | 판단이 애매할 때, 정리 층을 다시 만들 때 |
| 정리 | `wiki/` | 원본에서 만들어진다. 언제든 다시 만들 수 있다. 기준, 프로젝트 카드, 진행판 | 작업 중 매번 |

새 정보는 **항상 원본에 먼저** 들어간다. 정리 층에 직접 새 사실을 적지 않는다.
정리 층의 모든 항목은 자기가 나온 원본을 가리킨다.

## 불변 조건

구조를 어떻게 바꾸든 이 다섯 가지는 지킨다. 리팩토링이 끝나면 이 목록으로 스스로 점검한다.

1. 모든 기준은 원본(사례 또는 결정) 하나 이상을 가리킨다.
2. 모든 결정에는 날짜와 이유가 있다.
3. 기록은 지우지 않는다. `status: superseded`와 `superseded_by`만 표시하고 새 기록을 가리킨다.
   원본 파일에서 고쳐도 되는 건 이 두 필드뿐이다.
4. 같은 사실은 한 곳에만 있다. 두 문서가 다른 말을 하면 그게 할루시네이션의 시작이다.
5. 식별자와 파일명은 한 번 정하면 바꾸지 않는다.

## 승인 범위

- 원본에 추가하는 것은 에이전트가 알아서 한다.
- 실수를 기준으로 올리는 것(승격)은 에이전트가 제안하고 사용자가 승인한다. 절차는 `wiki/conventions.md`에 있다.
- 파일을 옮기거나 합치거나 대체됨 표시를 하는 **구조 변경**은 보고하고 승인받는다.
- 작업 산출물 PR은 검수를 통과했고 보고서 "확인할 것"이 "없음"이면 팀장이 머지한다. "확인할 것"에 적힌 것이 있으면 머지하지 않고 사용자에게 남긴다.
  "확인할 것"에 적는 위험한 변경: 데이터 삭제나 DB 구조 변경, 공유 타입·공통 모듈, 외부 서비스·API, 새 라이브러리, 인증·권한·비밀값, 테스트를 고치거나 지운 것, 요청을 에이전트 방식으로 해석한 것.
- 비밀값, 자격 정보, 고객 인프라 식별자는 어디에도 적지 않는다. 이 저장소는 GitHub에 있고 클라우드 에이전트가 읽는다.

## 어디서 시작하나

- 무엇을 열지 모르겠으면 `INDEX.md`
- 파일 형식과 식별자 규칙은 `wiki/conventions.md`
- 저장소가 답해야 하는 질문은 `tests/regression.md`. 리팩토링 전후로 같은 답이 나와야 한다.
