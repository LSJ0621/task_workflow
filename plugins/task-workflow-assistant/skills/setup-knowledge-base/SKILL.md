# 지식 베이스 설정

비서·팀장·검수자·사서가 읽고 쓸 지식 베이스를 준비한다. 한 번 하면 끝나는 일이라 사용자가 설정 파일을 열 일이 없게 하는 것이 목표다.
플러그인이 지식 베이스에 기대는 것은 네 가지뿐이다. 규칙 문서(`wiki/conventions.md`), 색인(`INDEX.md`), README의 불변 조건, 규칙 문서에 적힌 메모 위치. 나머지 구조는 사용자가 바꿔도 된다.

## 먼저 확인

`$KNOWLEDGE_BASE_DIR`이 이미 있으면 연결된 상태다. 사용자에게 "이미 연결돼 있다. 점검만 할지, 다른 저장소로 바꿀지"를 묻고 그에 맞게 간다. 없으면 아래 두 모드 중 하나를 묻는다. 사용자가 이미 말했으면 다시 묻지 않는다.

## 모드 1: 새로 만들기

1. 세 가지를 묻는다. 저장소를 둘 폴더(절대 경로), 저장소 이름, 소유자 표시 이름. GitHub CLI(`gh`)가 있으면 비공개 저장소도 만들지 함께 묻는다.
2. 초안을 복사하고 자리표시자를 치환한다.
   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/skills/setup-knowledge-base/scripts/bootstrap.py" <폴더> --name <이름> --owner <소유자>
   ```
   이미 있는 파일은 건너뛴다. 플러그인은 기존 지식 베이스를 덮어쓰지 않는다.
3. `git init -b main` 후 첫 커밋. GitHub 저장소를 만들기로 했으면 `gh repo create <이름> --private --source . --remote origin`. push는 사용자에게 묻는다.
4. 아래 "설정 저장"을 한다.

## 모드 2: 기존 저장소 연결

1. 경로를 받는다.
2. 계약을 점검한다.
   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/skills/setup-knowledge-base/scripts/check_contract.py" <폴더>
   ```
   필수 네 가지 중 실패가 있으면, 초안의 해당 파일을 보여 주고 추가할지 묻는다. 기존 파일은 고치지 않는다. 사용자가 자기 규칙을 이미 갖고 있을 수 있어서다.
   권장 항목(클라우드 세션 권한 `.claude/settings.json`, 비서용 `CLAUDE.md`(글쓰기 절 안내 한 줄 포함), 진행판 `wiki/board.md`)이 없으면 왜 필요한지 한 줄과 함께 추가를 제안한다. 클라우드 권한 파일은 셸 명령과 세션 도구를 허용 목록에 두는 두 줄이다. 클라우드 세션은 권한 무시 모드로 열리지 않아서 이 목록이 없으면 도구를 쓸 때마다 허용 창이 떠 자동화가 멈춘다.
3. 아래 "설정 저장"을 한다.

## 설정 저장

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/skills/setup-knowledge-base/scripts/save_setting.py" --dir <절대 경로> [--repo <원격 주소>]
```

`~/.claude/settings.json`의 `env`에 `KNOWLEDGE_BASE_DIR`과 `KNOWLEDGE_BASE_REPO`를 넣는다. 기존 설정은 보존한다. 환경 변수로 두는 이유는 모든 세션, 서브에이전트, 셸 명령에서 `$KNOWLEDGE_BASE_DIR`로 바로 보이기 때문이다. 사용자 설정 파일을 바꾸는 일이라 실행 전에 한 문장으로 알린다.

## 끝날 때

저장한 설정은 **다음 세션부터** `$KNOWLEDGE_BASE_DIR`로 보인다. 지금 세션에서 이어서 사서나 팀장을 쓰려면 경로를 직접 넘긴다. 이걸 말하지 않으면 사용자가 바로 다음 요청에서 "연결 안 됐다"는 답을 받는다.

두 줄로만 보고한다. 앞뒤에 다른 문장을 붙이지 않는다.
- **완료**: 만들었거나 연결한 경로, 계약 점검 결과, 설정 저장 여부. 그리고 "맥이 꺼져 있을 때는 이 저장소로 클라우드 세션을 열면 그 세션이 비서가 된다"를 이 줄 끝에 넣는다. 저장소 안 `CLAUDE.md`가 그 역할을 주기 때문이다
- **확인할 것**: GitHub 저장소 생성, 사용자 설정 파일 변경처럼 세션 밖에 남는 변경. 없으면 "없음"

## 하지 말 것

- 기존 지식 베이스 파일을 덮어쓰거나 고치지 않는다. 추가만 제안한다.
- push를 묻지 않고 하지 않는다.
- 초안 치환 외에 내용을 지어 넣지 않는다. 기록은 사서가, 기준은 실제 작업의 피드백이 만든다.
- 비밀값이나 자격 정보를 지식 베이스나 설정에 적지 않는다.
